**Build-time concurrency (B-1).** The build cap is 50 agents at once; the runtime caps (30 per sub-task, 200 per machine, §4 (part-03-personas-and-concurrency.md)) are a different ledger and do not apply to the build, and the build machine's own ledger is not the work runtime's ledger. Claude Code allows 20 concurrent subagents per session by default (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`, §6.1 (part-05-execution-constraints.md) row 1), so 50 is reached by splitting across the three build-machine sessions, each of which may run subagents (owner ruling): Worker1 as planner and lead (integration, half of the review buses) with the variable raised to 25, Worker2 as executor (authoring, scripts, tests, the other half of the review buses) raised to 25, and the desk for git with its default 20 but holding at most 5 build slots; review-bus orchestration is spread across Worker1 and Worker2 because one bus is 12 slots and a 25-cap session hosts at most 2 buses, which is where item 31's 4-bus figure comes from. A build ledger file `$TMPDIR/build-ledger/<session>.row` per session is summed by Worker1 before every dispatch and never exceeds 50 in total; the per-session variable is set in each session's launch environment and asserted at start (A5). Each wide item below is split into directory-disjoint pieces so the critical path shrinks; the split is only allowed where the pieces share no file (Rule 7), and a one-agent integration step follows every split.
