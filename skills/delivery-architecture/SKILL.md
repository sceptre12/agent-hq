## Trigger
Use when a confirmed brief must become an epic tree and a human-reviewable architecture doc with dispatch, testing and release sections (card 3, stage 2). The conductor invokes it after `gates/H0.<run-id>.ok` exists, and again after an `H1.changes` verdict (the notes bind). Model-invocable (D16).

Personas (part D2.1): you are the `architect` (design tier). You dispatch one `ticket-decomposer` (execute tier) with `references/decomposer-brief.md`; your own brief is `references/architect-brief.md`. Both carry the COMMON block; pass it unchanged to any agent you brief.

Outputs (part A.6, planes part D6): in `PLANS_DIR`: `drafts/<slug>.md`, `drafts/index.md`, `architecture.md`, `test-plan.md` v0, `release-plan.md` v0, `review-architecture.md`, `h1-packet.md`; at the repo root: `contracts/`. Every file is written to a temp file in its own directory and `mv`d into place (part A.1 atomic writes). Templates (item 27): `references/templates/{ticket,architecture,test-plan,release-plan}.md`; this skill never edits them. Gate files carry the run id (`<gate>.<run-id>.ok`, part A.2.1, AM-5 26); a short name such as `H1.ok` below means that file.

## Steps
0. **Validate inputs (part D1, D2.2 row 3).** Inputs as `NAME=value`: `RUN_HOME` (path), `PLANS_DIR` (path; holds `brief.md`, `facts.md`), `REPO_PROFILE` (`<abs path>@<sha>`). Check every field and the profile keys this skill reads (`e2e.harness`, `durations.*`, `review_profile.*`; `release_tags.*` optional), print one `INPUT-ERROR <NAME> <reason>` line per failing field, then stop: no retry, no prompt, nothing written. `RUN_HOME` absent prints exactly `INPUT-ERROR RUN_HOME missing`. When `RUN_HOME` passes, also read `RUN_HOME/state.md` (part A.2, `interfaces/part-a-state.md:54-91`; a read under `RUN_HOME`, not a new input): `orchestrator_tier` (required) and `security_audit` (absent means `guidance`, the A.2 default). Cases: `references/step0-inputs.md`. If `RUN_HOME/gates/H1.<run-id>.changes` is live, this is a re-entry: run `references/step0-inputs.md` §Re-entry first (old record and packet renamed, notes read); every note is a binding change.
1. **Find existing docs; update, never duplicate (Rule 5, `config/CLAUDE.md:32`).** Search the repo root (the parent of the `plans/` directory holding `PLANS_DIR`) for `docs/`, `architecture/`, `plans/*/architecture.md`, `contracts/`, ADRs and the files `brief.md` names. For each doc that covers the same surface: validate it against source (step 9 method) and update it in place before step 10, so a review round reads the edit; a stale doc is corrected, not copied. Each updated doc's repo path is added to the `st0` scope in item 5 (`references/tree-rules.md` §Item 5), so the plan PR commits it. Record each found doc and its decision (update, cite, or out of scope) for `architecture.md` item 4 and item 14. Every existing doc you update goes into `ARTIFACTS` (step 10) and the packet table (step 14), so it is reviewed and accepted with the rest.
2. **Draft the typed tree, spikes first.** From `brief.md` and `facts.md`, outline one `Epic`, then `Spike` children for every unknown that blocks a design choice (each timeboxed, with its question and exit), then `Story`, `Task`, `Subtask` children. Types are exactly the D2.1 set `Epic|Spike|Story|Task|Subtask`. Merge order follows owner ruling D5 (one PR per sub-task). Rules: `references/tree-rules.md`.
3. **Mint slugs, write the drafts, then the index.** Mint one slug per node (`^[a-z0-9][a-z0-9-]*$`, never `index`, unique; rule in `references/tree-rules.md`). Dispatch the `ticket-decomposer` with the tree inline; it writes `drafts/<slug>.md`, each opening with YAML front matter of exactly `slug`, `issuetype`, `parent` (`-` for the epic), then the `templates/ticket.md` body, which opens with the short header carrying team, priority and requested-by (part D3 "Ticket parents", `interfaces/part-d-enums-topics.md:110`, AM-4; the front matter stays three keys, and the Jira parent carrier is `ticket-clerk`'s, part B4 `jira-create`): Gherkin AC (happy, failure or edge, observability) for every Story, agent fields (scope globs, persona and tier, blocked-by, lanes, tests with e2e `new|updated|none` + reason, done token, verifier, budget from `durations.*`). No contract file exists yet, so each contract a draft reads or writes is written `PIN-TBD:<contract name>`; step 8 replaces every one. Validate every `issuetype` against D2.1 (`INPUT-ERROR issuetype enum` on a miss, then stop). Write `drafts/index.md` last: line 1 `DRAFTS: <n> drafts`, `<n>` the number of `drafts/*.md` other than `index.md`, then one row per draft in publish order (parents before children, spikes first). Drafts stay local until `H1.ok`; no `jira-create` here.
4. **Write `contracts/`.** One file per shared value or cross-unit contract (API shape, event, schema, config key, file format, fixed port). Each contract has exactly one owning document; siblings cite it by pin (`contracts/<file>@<sha>` or `<file>:<line>`) and never restate it (D63, D67). Rules: `references/contracts.md`.
5. **Write `architecture.md` in the part-04 §5.2 order** from `templates/architecture.md`: header block with exactly one line `security_sensitive: yes` or `security_sensitive: no` (step 5a), then items 1-14. Item 3: the template's component table, then the contract sub-table (`contract | owner path | consumers`, one row per contract; each fixed port a component needs is one row there, named `port <port> <service>`, its bind and reason in the owning file; `references/contracts.md`), so the dispatch plan and lanes can claim it with `tools/port-check.sh --claim` before launch (part A.5.2); this skill binds nothing, claims nothing and writes no catalog `port` row. Item 3 restates the primary repo and names any other repo (part A.1). Item 5 is the template's sub-task table (`references/tree-rules.md` §Item 5). Item 7 carries the lanes, shared-file owners, units that must not run in parallel, and the ports to claim, each port as a cite to its item 3 row, never a second copy. Item 12 is filled at step 10, before round 1, and never changed after (step 10). Item 13, the human acceptance block (ACCEPT / CHANGES / REJECT, name, date), is written blank. Link the profile `@<sha>`, never copy it (D22). Over about 500 lines: a landing page plus parts (`references/tree-rules.md` §Large epics).
   - 5a. **Set `security_sensitive`** from `references/security-sensitive.md` (owner ruling OQ-1, `architecture/delivery-workflow-sources/owner-decisions.md:88-89`; INTERFACES AM-3, `architecture/delivery-workflow/INTERFACES.md:25`). When unsure, `yes`.
6. **Write `test-plan.md` v0** from `templates/test-plan.md` (part-04 §5.4). The e2e statement follows `e2e.harness` (D17; part-03 §3.6 step 1): `nlta`: every user-visible Story gets an e2e unit row (`.feature` path planned, flow named). `none`: `architecture.md` item 8 names the gap in one line per affected Story, and `test-plan.md` carries human hand-test rows post-merge for those Stories. Every Story AC maps to a test row. A3 rows: `sub-task` is an item 5 sub-task id (`st<N>`): the Story's own row, or, for a Story split into `Subtask`s (sub-task `-` in item 5), the `st<N>` of the Subtask that builds the user-visible behaviour; `unit slug` is the Story's draft slug either way; the batched `st<N>:` `.feature` list is written at v0 with the planned paths and is final before H-e2e, whose `ref=` is its sha256 (part A.2.1, `interfaces/part-a-state.md:102`).
7. **Write `release-plan.md` v0** from `templates/release-plan.md` (part-04 §5.5). The step table's first column is `step_id` (`^[a-z0-9-]+$`, unique in the plan; you mint the ids, `release-track` keeps them, and a re-entry keeps every existing id), then the step, its owner `agent` or `human` (D15: production deploy, flag flip, money, prod data, external publication, store submission are `human`), and the `tag` for a tag step; each step has its exact prepared command and rollback. A tag step is planned only when the profile has `release_tags.used: "yes"`, and its `tag` matches `release_tags.pattern` (part A.2.2, `interfaces/part-a-state.md:138-142`); with no entry, no tag step (the desk refuses it). With `used: "yes"` and `pattern` absent, not an anchored `^...$` ERE, or `approval` absent or outside `none|human`, plan no tag step and name the malformed key in `architecture.md` item 10 (the desk answers `REJECTED policy`, `interfaces/part-a-state.md:142`). A tag step under `approval: human` has owner `human` (its gate is `H-prod.<step_id>.ok`, part A.2.1, `interfaces/part-a-state.md:104`).
8. **Re-sync drafts (always on the first pass, since step 3 leaves `PIN-TBD:` placeholders that K14 forbids, `references/tree-rules.md` K14).** Re-dispatch the decomposer (same brief) to replace every `PIN-TBD:` with the real pin, and again whenever steps 4-7 or a fix change a child's scope, contract pin or test expectation; rewrite `drafts/index.md` after any draft change. No `PIN-TBD:` may remain (K14).
9. **Verify claims against source.** Every factual sentence in `architecture.md`, `contracts/` and the drafts cites a `facts.md` row or a command you ran (`measured: <cmd -> result>`); a design choice that is not a fact (a new endpoint path, an error code) is marked `proposed`. Re-run the command behind each load-bearing fact. A doc that contradicts source is the stop condition: re-measure, fix the doc; if a `facts.md` row itself is wrong, stop and report it to the conductor (the fact is re-measured before anything else, D51).
10. **Call `review-tailor`** with every D2.2 row 4 input. Mint `SLUG=run-doc-<n>`, `n` = 1 + the number of existing `RUN_HOME/review-tailor-run-doc-*.md`. Pass `RUN_HOME`, `SLUG`, `ARTIFACTS` (comma-separated absolute paths: `architecture.md`, its parts, `contracts/*`, `test-plan.md`, `release-plan.md`, `drafts/*.md`, every existing doc step 1 updated), `KIND=doc`, `STAKES`, `CONTENTION`, `NOVELTY`, `SECURITY_AUDIT` (the step 0 `state.md` `security_audit`, unchanged), `ORCHESTRATOR_TIER` (the step 0 `state.md` `orchestrator_tier`). Values: `references/review-handoff.md`. Read `RUN_HOME/review-tailor-<SLUG>.md`: line 1 must match `^RUNG: (0|1|2|2b|3|4) seats: [0-9]+$` (`INPUT-ERROR rung enum` otherwise, then stop). Card 3 floor: 1 for a story, 2b for an epic, 4 for a one-way door. The run rung is the higher of the record rung and the floor: **an epic's review rung is at least 2b (7 seats), whatever `review-tailor`'s generic rubric returns** (design card 3; owner ruling 2026-10-26, `architecture/delivery-workflow-sources/owner-decisions.md:95`; INTERFACES D8 D2.2 row 4, AM-5 15); a raised rung is recorded as in `references/review-handoff.md` §2. Then fill `architecture.md` item 12 now, before round 1, with what is known and pointers only (`references/review-handoff.md` §2a), so its bytes are reviewed by every round and never change after the last one (D1).
11. **Run the loop of the run rung** (step 10; `references/review-handoff.md`): Rung 1 `doc-reviewer` with `skills/doc-reviewer/references/delivery-doc-checks.md`, fix, `fix-verifier`; Rung 2 `panel-consultation`; Rung 2b `review-7-panel`; Rung 4 `panel-review`. At Rungs 2b and 4 one review orchestrator runs the loop (D35); at Rungs 1 and 2 there is none and you dispatch the reviewer, the fixer and `fix-verifier` yourself. The pre-round slot runs before round 1 and after every fix: the G48 check plus the `references/tree-rules.md` §Checks K1-K15, and its fails are fixed (then re-checked) before any seat reads, so every fix is seen by a review round (D1). Relay the D57 freeze trigger stated in the record into the orchestrator brief. A finding that arrives mid-round is queued for the next round start or a separate pass, never injected (G46). The fixer is never you, the author; `fix-verifier` runs after each fix. Stop at 0 Blocking / 0 Medium (then the mechanism's Low pass and its verifier), or at a round-3 NOT MET (owner ruling D7): no fixer, no `fix-verifier` and no further round follow it, and the orchestrator brief says so; that synthesizer's open B/M rows go to the packet as they are, and the owner decides.
12. **Record the checks.** Re-run K1-K15 on the final artifacts and paste each command and result into the review record. A failure here (only the Low pass can cause one) is not fixed outside a review round: it is listed as an open finding in the record and the packet (a default of this skill).
13. **Write the review record.** Write `review-architecture.md` to a temp file in `PLANS_DIR`: line 1 exactly `ARCH: ready`; lines 2-4 the fixed header block `STAKES: <value>`, `CONTENTION: <value>`, `NOVELTY: <value>` (bare D2.1 enum values, the ones passed at step 10; `references/review-handoff.md` §1; `delivery-dispatch-plan` step 12 and, through the conductor, `release-track` read them, INTERFACES D8 and C8 29-28, AM-5 15), then a blank line; then the record body (the reason for each of the three values, rung and any `rung raised:` line, mechanism, rounds, final B/M/L, check results, queued findings, open findings if round 3, the records directory and loop ledger paths of `references/review-handoff.md` §3 with every round record path) and a link to `RUN_HOME/review-tailor-<SLUG>.md`; the seat table is linked, not copied (D22). Do not move it into place yet.
14. **Write `h1-packet.md`** (one page, `references/h1-packet.md`): decisions needed (on a re-entry, one `note <k>` line per note), risks, open findings if round 3 was reached, and what the human is accepting: one row per file with its absolute path and sha256, the files as reviewed (each draft, `drafts/index.md`, each contract, `architecture.md` and each part, `test-plan.md`, `release-plan.md`, each updated existing doc, the review record). It tells the human the desk line `GATE <run-id> H1 ok|changes|reject <text>` (part B8) and what each verdict means for the listed decisions and open findings (`references/h1-packet.md` §How to answer). Then `mv` the review record into place, so `ARCH: ready` is the last thing written.
15. **Stop.** Hand the packet path to the conductor. H1 is the desk's and the human's: you write no gate file and publish nothing (spec 15 §4 H1 row; drafts stay local until `H1.ok`, part A.2.1).

Spec map (spec 15 §8 item 3): 5a and 8 are sub-steps of the spec's `architecture.md` and drafts steps; the record is written at 13 but moved into place at 14, after `h1-packet.md`, so `ARCH: ready` is "written last" (spec 15 §4).

## Red flags
| Rationalization | What to do instead |
|---|---|
| "The sibling contract is short; I'll restate it here for readability." | Cite it by pin. One owning document per cross-unit contract (D63, D67); a restatement is the cross-document conflict reviews keep finding. |
| "The human will accept anyway; I'll create the Jira tickets now." | Drafts stay local. `ticket-clerk` publishes through the desk only after `RUN_HOME/gates/H1.<run-id>.ok` exists; the desk refuses `jira-create` until then (part A.2.1 Enforcement, `interfaces/part-a-state.md:107`). |
| "This epic looks small, skip the loop." | Call `review-tailor` and run the mechanism it names, raised to the card 3 floor when below it: an epic gets at least 2b, 7 seats (owner 2026-10-26). The floor is card 3's, not your judgement. |
| "That number is well known; no need to cite it." | Every fact cites a `facts.md` row or a command you ran. No measured source, no fact. |
| "A seat just found something; I'll pass it to the running round." | Queue it for the next round start or a separate pass (G46). |
| "The doc disagrees with the code; the doc is probably newer." | Measure. The doc contradicting source is the stop condition. |
| "I'll fix the review findings myself; I know the doc best." | The fixer is never the author. You hand findings to the loop's fixer. |
| "Round 3 still has a Medium; one more round will close it." | D7: stop after round 3; the open findings go in the packet for the owner. |
| "There is an old architecture doc, but starting fresh is cleaner." | Update the existing doc (Rule 5, `config/CLAUDE.md:32`); a stale doc is corrected, not duplicated. |
| "The repo has no e2e harness, so e2e does not apply." | Name the gap in `architecture.md` item 8 and add human hand-test rows to `test-plan.md` (D17). |
| "The service needs port 4200; I'll claim it now to be safe." | Name the port in item 3. The dispatch plan and lanes claim it before launch (A.5.2); this skill claims nothing. |
| "The epic touches auth, so I'll run `security-audit` now." | Write `security_sensitive: yes`; the conductor sets `SECURITY_AUDIT`. This skill runs no audit and writes no audit files. |
| "I'll copy the profile values into the doc." | Link `REPO_PROFILE` `@<sha>` (D22). |
| "I'll write `ARCH: ready` first so the conductor sees progress." | It is written last, after the loop and the checks, with the packet already in place. |

## Exit criteria
- [ ] Step 0 passed, or only `INPUT-ERROR` lines were printed and nothing was written.
- [ ] Existing docs found in step 1 were updated or cited, none duplicated.
- [ ] `drafts/index.md` line 1 matches `^DRAFTS: [0-9]+ drafts$` and `<n>` equals the number of drafts; every draft stem matches `^[a-z0-9][a-z0-9-]*$`, is not `index`, and its front matter is exactly `slug`, `issuetype` (D2.1), `parent`; exactly one `Epic`, with `parent: -`; every other `parent` is a draft slug.
- [ ] Every draft Story has Gherkin AC with a happy path and a failure path.
- [ ] Every cross-unit contract has exactly one owning document; no sibling restates it.
- [ ] Every user-visible Story has an e2e unit (`nlta`) or a gap line in `architecture.md` item 8 plus human hand-test rows in `test-plan.md` (`none`).
- [ ] `architecture.md` has items 1-14 in order, exactly one `security_sensitive: yes|no` header line, fixed ports named once in the item 3 contract sub-table and cited from item 7, and a blank item 13.
- [ ] `release-plan.md` step ids match `^[a-z0-9-]+$`, are unique, and every step is `agent` or `human`.
- [ ] The loop reached 0 Blocking / 0 Medium, or stopped after round 3 with the open findings in the packet.
- [ ] Every check of `references/tree-rules.md` §Checks passed before each round and its final result is in the review record (a final failure is an open finding in the packet).
- [ ] `review-architecture.md` line 1 is exactly `ARCH: ready`, lines 2-4 are `STAKES: `, `CONTENTION: `, `NOVELTY: ` with bare enum values, it links `RUN_HOME/review-tailor-<SLUG>.md`, and it was moved into place after `h1-packet.md`.
- [ ] No draft was published, no gate file written, no port claimed, no audit run, no web fetched, no money or spend metric written (B-4).
