# Executor rules

For the separate `cleanup-executor` (mechanical tier; persona brief `skills/delivery-run/references/briefs/cleanup-executor.md`), the host session that dispatches it, and the `validator` spot-check. The per-kind verify and cleanup commands are the A.5.1 table (`architecture/delivery-workflow/interfaces/part-a-state.md` A.5.1); apply it by citation. This file holds only what A.5.1 does not: guards with their evidence, already-gone rows, the order across kinds, the host hand-off, and the spot-check. "Flag" means the `kept` row plus one `## residual` line naming the row id and reason.

## Ground rules
- Input: the `## dry-run` table and the `## approved` list, passed verbatim in the dispatch by the approver. Before acting, write both verbatim into the temp record (`references/cleanup-record.md`). Act only on row ids in `## approved`; a path not in that list is never touched (D9).
- One `rm` per literal path, no `-r` on a computed or globbed path. A directory is removed by `rm -r <literal path>` only for the registered `tmpdir`, `clone` or `bus` `data_dir` handle, after re-measuring.
- Re-measure first (`du -sk`, `find <path> -type f | wc -l`, `.git` included). A mismatch with the dry run is a stop: write the mismatch to `## residual`, delete nothing for that row.
- The executor deletes or releases; it never moves or copies files. A failed guard is `catalog.sh keep <kind> <handle> <reason>` and a flag, never a workaround. A guard that could pass only by deleting a non-catalog path is a stop and a report (spec §11).
- A denied command or a sandbox or classifier block is a stop and a report. Do not wrap, reroute or retry through another channel.
- Append every command you ran, with its exit code, to `## executed` of the temp record as you go (a re-dispatch continues from it).
- Every `catalog.sh` call takes `RUN_HOME` inline and `WORKTREE_BASE` inline when the profile `worktree_base` is set (omitted when unset or empty). Rows are matched by `kind`+`handle`, never by the row id alone (every append makes a new row id, so `## approved` ids name the dry-run rows). An approved `keep <reason>` is applied as `catalog.sh keep <kind> <handle> <reason>`. A branch whose worktree row ends `kept` is `keep branch <handle> worktree-kept`. After each success: `catalog.sh release <kind> <handle>`; on a failed attempt `catalog.sh fail <kind> <handle>`; for a guard `catalog.sh keep <kind> <handle> <reason>`.

## Already-gone rows (audit `GHOST`, dead pid)
`catalog.sh release <kind> <handle>` alone only where nothing can remain: `process` (dead pid: `kill -0` fails with "no such process"; `catalog-audit.sh` reports any `kill -0` failure as `GHOST`, so re-test before release), `pm2-app` (not in `pm2 jlist`), `tmpdir`, `file`, `clone` (`test -e` false), `worktree` (not in `git worktree list` and `test -e` false on the path part before `#`; a path still present is `keep worktree-residue`). The others still carry residue, because `catalog-audit.sh` checks only one fact (`tools/delivery/catalog-audit.sh` `audit_check`): `port` (no listener) still needs its `released` claim, then `catalog.sh release`; `bus` (endpoint pid dead) still needs `pm2 delete` when `pm2 jlist` lists its app and the `data_dir` `rm` when `test -e` is true; `branch` (local ref gone) still gates the remote by D8 through the hand-off.

## Order across kinds (skill default)
`cron`, `bgtask` (host hand-off), `pm2-app`, `bus`, `process` first; then `port` (A.5.1: only after the listener is stopped); then `worktree`; then `branch` (git refuses to delete a branch checked out in a worktree); then `tmpdir`, `file`, `clone` (a clone may hold the worktrees above). `lane-lease`, `db` and the no-delete kinds have no order constraint.

## Guards and evidence, per kind (commands: A.5.1)
- worktree: A.5.1 guard. `git -C <path> status --ignored --porcelain` prints nothing (one command covers `git status --porcelain` and `git status --ignored`, so a dirty tree and any ignored file both fail; this skill captures nothing, so any ignored file such as `.env` is uncaptured), else `keep worktree <handle> ignored-or-dirty` and flag; PR open or merged. PR evidence: `state.md` `subtasks[<row subtask>].state` is `pr-open` or `merged` (A.2), or `MERGE_RECORD` for `st<N>`. The detached `pm` worktree (stages 6-7, a worktree of `default_branch` with no PR, A.2) passes this PR condition with the `pm` evidence of SKILL.md Step 0 (owner-accepted answer to OQ-B; INTERFACES 1.10.0 A.8 A.5.1, AM-5 19); its clean-and-no-ignored condition still applies. No PR evidence for any other row (every `run` row): keep with reason `no-pr-evidence` and flag.
- branch: D8, local and remote alike: content-merged into the profile `default_branch` (A.2.2: "main" in the design means this key; read it from the profile pinned by `state.md` `repo_profile`; written `<default_branch>` below), tested by the B5 `branch-delete` content-merged method (`architecture/delivery-workflow/interfaces/part-b-desk.md` B5: ancestor, then per-commit patch-id via `git cherry` with no `+` lines, then the squash patch-id recipe) against the `sha` that a desk `fetch` of `<default_branch>` returned (B6 `fetch` result), never against a local `<default_branch>` that may lag. A handle `<base>` other than `<default_branch>` does not widen the test. `merge_sha` from `MERGE_RECORD` `merge_sha=` (`st<N>`) or `state.md` `subtasks[<row subtask>].merge_sha`; it is never set for `pm` or `run` (A.2); empty means `keep branch <handle> no-merge-sha` and flag. Remote first, local after: the local `git branch -D` runs only after the desk `branch-delete` returns `DONE`, so a `REJECTED` never leaves a `kept` row over a deleted local ref. The skill never runs `git push` or `gh`. No remote (`MERGE_RECORD` `merge_reach=local`, or `git -C <repo> remote` prints nothing): local-only deletion, no desk `fetch` or `branch-delete`; the D8 test runs against the local `<default_branch>` sha, the `git branch -D` follows a pass, and the `## residual` line says "no remote" (A.8 A.5.1, AM-5 19-F6).
- process: the pid from the row only, `kill -0` before (a "no such process" failure is an already-gone row) and after (must fail with "no such process"; an "operation not permitted" failure means the pid is alive but not signalable from this session: stop and report, never treat it as gone). Never by name or pattern. Identity (skill default): before `kill`, `lsof -a -p <pid> -d cwd` shows a cwd under `RUN_HOME` or `worktree_base`, or the pid is the listener of an approved `port` row; else `keep process <pid> pid-identity` and flag (a reused pid).
- port: stop the listener first, and only when it is the process of a catalog row in `## approved`; a listener that is not a catalog row keeps the port row and is reported in `## residual` (D9). After `lsof` shows no listener, find the claim row in `~/projects/agent-hq/tools/ports.tsv` (read-only) with this `port` and `project` `<run-id>` (A.5.2) whose latest status is not `released`, and repeat it exactly: `~/projects/agent-hq/tools/port-check.sh --claim "<port>" "<bind>" "<container_port>" "<service>" "<project>" released "<source>" "<note>"`, every field copied from that row and quoted (`bind` may be `*`, `note` may hold spaces; exactly 8 positionals after `--claim`; cite `skills/port-claim/SKILL.md` step 4). No such claim row: `keep port <port> no-claim-row` and flag (skill default). A refusal (any non-zero exit; `port-check.sh` refuses a claim while its check is not free, and exit 3 always): `keep port <port> port-claim-refused`, flag, stop for that row. Never pass `--force` (`skills/port-claim/SKILL.md` step 3: never in a delivery run). On exit 0: `catalog.sh release port <port>`. Never edit `ports.tsv` by hand.
- bus: A.5.1 as written; evidence: `pm2_app` from the row's `bus.endpoint`: `RUN_HOME/<subtask>/bus.endpoint` for a sub-task bus (C5.1), `RUN_HOME/review/<subtask>/<review-id>/bus.endpoint` for an in-run review bus whose `data_dir` is `.../<review-id>/bus/` (D5, AM-5 10-B2). No `bus.endpoint` file: `keep bus <handle> no-endpoint` and flag. Its port is its own `port` row.
- pm2-app: the exact name from the row only.
- cron, bgtask: the tool id from the row only; `CronList`/`CronDelete` and `TaskList`/`TaskStop` are host-session tools, so the host session runs them through the hand-off below (owner-accepted answer to OQ-C; INTERFACES 1.10.0 A.8 A.5.1, AM-5 19). A `bgtask` `TaskStop` is always followed by the A.5.1 orphan sweep (C7, hand-off step 2).
- tmpdir, file: no guard beyond A.5.1 and the re-measure.
- clone: the same ignored-files check as a worktree: `git -C <path> status --ignored --porcelain` prints nothing, else `keep clone <path> ignored-or-dirty` and flag; never delete a clone holding an ignored file such as `.env` (spec §4 never-touch: credentials). Then (skill default) `git -C <path> log --branches --not --remotes` prints nothing (no unpushed commit), else `keep clone <path> clone-unpushed` and flag.
- db: run the lane's `lanes[].db.cleanup_cmd` (A.5.1; A.2.2, AM-5 19, owner-accepted answer to OQ-D) only when the profile pinned by `state.md` `repo_profile` carries that key for the lane; absent there, `keep db <handle> no-profile-cmd` and flag.
- tag, container, image, workspace, lane-lease: A.5.1 as written (no delete verb for the first four: keep, report with the correlation id).

## Host hand-off (B1, B3, B4, B6)
The executor is a subagent: it cannot send `DESK` lines (B1 non-lead requesters) or use `CronDelete`/`TaskStop`. The host is the lead in mode `subtask`, the conductor in mode `final`.
1. Executor, round 1: for each repo with a remote and an approved branch row, write a `fetch` request `{repo, ref: "<default_branch>"}` with `DELIVERY_ROOT=<root> desk-req.sh <run-id> <token> fetch <fields-json-file>`; `<token>` is `SUBTASK` (`st<N>` or `pm`) in mode `subtask` and `run` in mode `final` (B1). List each approved `cron`/`bgtask` id as a host action. Record ids and printed `DESK` lines in `## executed`, return them to the host, finish the other rows.
2. Host: send each `DESK` line to `desk` by `SendMessage` (a `claude -p` lead writes `RUN_HOME/<subtask>/outbox/<id>.desk`, B1) and poll `RUN_HOME/desk/<id>.out` per B1 (5 minutes, one resend of the same id, 5 more minutes, then the host renames `<id>.req` to `<id>.req.noreply` and writes the B1 `ESCALATE` `human-step`). Run each host action (`CronList` then `CronDelete <id>`; `TaskList` then `TaskStop <id>`, then the A.5.1 orphan sweep of C7: list processes by cwd under that task's worktree with `lsof`, register each as a catalog `process` row (`catalog.sh register` then `start`) before anything acts on it, and add its row id to `## approved` as `delete`; C7 order: TaskStop, orphan sweep, then free rows) and note the result. A host without the tool notes `no-host-tool`. Re-dispatch the executor with the `.out` paths, the notes and any orphan rows (the executor kills them by pid under the `process` guard).
3. Executor, round 2: record every result in `## executed`. Host actions: done is `catalog.sh release`, else `keep <kind> <id> no-host-tool` and flag. `fetch` `DONE`: run the D8 test against its `sha`; pass writes `branch-delete` `{repo, branch, merged_into: "<default_branch>", merge_sha}` (`repo`, `branch` from the handle `<repo-abs-path>#<ref>@<base>`) the same way, and the host repeats step 2.
4. Executor, round 3: `branch-delete` `DONE` (`deleted`, `merged_check`): local `git branch -D <branch>` if the ref exists, then `catalog.sh release branch <handle>`.
5. Any other outcome keeps the row (local ref untouched) and flags it, never another channel (B2.1): a failed D8 test is `not-merged`; `<id>.req.noreply` is `desk-noreply` (B1 treats it as terminal); `REJECTED <id> | <code>` is `desk-<code>`. Terminal codes (`sender`, `schema`, `hash`, `repo`, `policy`) are never resent and go to the owner by the host's C2 `ESCALATE` (`architecture/delivery-workflow/interfaces/part-c-waves-control.md` C2, reason `human-step`). `marker` is kept and flagged without resend (spec §4 Branch-delete row). Other curable codes (`order`, `stale-session`, `gate-missing`, `action-failed`) may be resent once the cause clears, with a fresh id on the same channel (OP5 B); until then, kept.

## Abandoned run (`stage: stopped`)
Mode `final`, no `MERGE_RECORD`. Unmerged branches and their worktrees are `kept` and flagged (D8, D9). Processes, ports, leases, buses and temp dirs are released as usual.

## Spot-check protocol (`validator`)
A different agent from the executor and the approver, and the only one that runs these checks. For every path or id in `## executed`: `test -e` is false; `kill -0` fails; `git worktree list` lacks the worktree; `git show-ref --verify` fails for a deleted local ref; `lsof` shows no listener and `port-check.sh <port>` shows no claim that is not `released`. Then the catalog: `catalog.sh list --live --subtask <st>` (mode `final`: `list --live`) is empty of build resources, and no row of the scope is latest `planned`, `live` or `failed` in `catalog.tsv`. Append one line per check, then `SPOT-CHECK PASS` or `SPOT-CHECK FAIL <n>`, to `## residual` of the temp record (the last section, so an append). A fail goes back to the approver; it is not fixed by the validator.
