## B2. Line grammar (ADR 0055 §1, verbatim, `decisions/0055-desk-verb-permission-tiers-02.md:52-56`)

```
DESK     <id> | <verb> | <abs path to RUN_HOME/desk/<id>.req> | sha256=<hex>
DONE     <id> | <verb> | result=<abs path to RUN_HOME/desk/<id>.out> | <one-line verdict, no imperatives>
REJECTED <id> | <reason: sender|schema|hash|repo|marker|order|policy|stale-session|gate-missing|action-failed>
```

**Line regexes (`DEFAULT (integrator)`, row R4-J6; POSIX ERE, `INTERFACES.md` §Regex dialect):** the column alignment of the block above is display only; a receiver accepts one or more spaces after the keyword and a sender writes one. `<ID>` below stands for `[a-z0-9-]+-(st[0-9]+|pm|run)-[0-9]{8}T[0-9]{6}Z-[0-9]+`.

```
^DESK +(<ID>) \| ([a-z-]+) \| (/[^ ]+) \| sha256=([0-9a-f]{64})$
^DONE +(<ID>) \| ([a-z-]+) \| result=(/[^ ]+) \| ([^|[:cntrl:]]+)$
^REJECTED +(<ID>) \| (sender|schema|hash|repo|marker|order|policy|stale-session|gate-missing|action-failed)$
```

`<verb>` must be a B4 verb (else `schema`); the `DESK` path must equal `RUN_HOME/desk/<id>.req` (else `schema`); `<hex>` is 64 lowercase hex. A `DESK` line that does not match is not a request: the desk logs it and replies nothing (the requester's B1 no-reply rule applies). "No imperatives" in the `DONE` verdict is an authoring rule, not machine-checked.

The design §6.3 line lists nine codes; the tenth, `action-failed`, is the owner's (2026-10-26, OP10 A, `owner-decisions.md:72`; design errata E14).

- **`DONE` form (owner 2026-10-26, OP2 A, `owner-decisions.md:64`):** the long grammar-block line, with `<verb>` and `result=`. The shorter `DONE <id> | <one-line verdict>` in §6.3 prose and card 15 is design errata.
- `<id>` = `<run-id>-<subtask>-<utc>-<n>`, regex `^([a-z0-9-]+)-(st[0-9]+|pm|run)-([0-9]{8}T[0-9]{6}Z)-([0-9]+)$` (groups 1-4: run-id, subtask, utc, n; numbered groups, POSIX ERE; group 2 is hyphen-free, so the split is unique); `<utc>` is `yyyymmddThhmmssZ` and `<subtask>` is the reserved token `run` for a conductor request that belongs to no sub-task (owner 2026-10-26, OP7 A, `owner-decisions.md:69`); `<n>` is a per-run counter allocated by `desk-req.sh` under `mkdir RUN_HOME/desk/.lock`. Producer `desk-req.sh`; consumer `delivery-desk`.
- **Idempotency (ADR 0055 §3, `decisions/0055-desk-verb-permission-tiers-02.md:185-191`; order FROZEN (integrator, ADR 0055 [freeze])):** a repeated `<id>` with a stored `.out` returns the stored `.out` and does not act, whatever the `sha256=` on the repeat line; the replay is answered before the copy and hash (B3 steps 1-2), so a replay whose sha256 differs gets the stored result, not `hash` or `schema`. A `REJECTED` is stored as `.out`, so a replayed rejected id returns the stored `REJECTED`; a resend after a curable code (B2.1) uses a fresh id (new `<n>`), a terminal code is never resent (owner 2026-10-26, OP5 B, `owner-decisions.md:67`). No `.out` is written for a `sender` reject, so an unregistered sender cannot pre-claim an id. Before acting (B3 step 9) the desk creates the directory `desk/<id>.inflight` (`mkdir`, atomic claim; `DEFAULT (integrator)`) and right after it writes the file `desk/<id>.inflight/target` holding one line `<verb> <target>`; on a repeat id with `.inflight` and no `.out` it reconciles by read-back (PR, ref, issue or tag already present) before acting again. **Duplicate-action guard for a fresh-id resend (`DEFAULT (integrator)`):** the file `<id>.inflight/target` holds one line `<verb> <target>` (`target`: `repo#branch@expect_head` for `push` and `pr-create`, `repo#branch` for `branch-delete`; `repo#pr` for `pr-merge`, `pr-attach`; `repo#tag@sha` for `tag-push` (row R4-J8); the issue key or parent key plus summary for `jira-*`; `package@version` for `publish`; `payload_path` for `test-report-push`); before step 9 the desk scans `desk/*.inflight/target` for the same `<verb> <target>` under any id with no `DONE` `.out`, and when one exists it reads the target back first: an action already present is answered `DONE` from the read-back without acting, else it acts; for `push`, `pr-create` and `tag-push` "already present" means the remote ref (or the PR head) equals the target's `@<sha>`, so a fresh-id push of a new head is never answered from an older inflight (`DEFAULT (integrator)`, row R4-J8). So a fresh-id resend after `action-failed` (OP5 B) is reconciled even though its id differs.
- `REJECTED` keeps the installed `<id> | <reason>` layout (M13). No trailing detail on the line; the detail is in the `.out` `detail` field (owner 2026-10-26, OP1 A, `owner-decisions.md:63`).
- `<hex>` is the sha256 of the request file as the sender wrote it.
- **Id-form collision (FROZEN (integrator, ADR 0055 [freeze]), `decisions/0055-desk-verb-permission-tiers-02.md:219-223`):** `<run-id>-<subtask>` always matches `^[a-z][a-z0-9]*-[0-9]+-[0-9]{8}(-[0-9]+)?-(st[0-9]+|pm|run)$` (part A.1 run-id shape plus the `<subtask>` set); a -02 profile name never contains the 8-digit date segment (profiles checked 2026-10-26: none match; the move checks the work environment's profile list against the same regex), so the two id forms never collide. A receiver also tells them apart by the request line the `<id>` came on.

### B2.1 Reason codes (ADR 0055 §2 scope, `decisions/0055-desk-verb-permission-tiers-02.md:138-148`; check-to-code mapping and class fixed here)

Each code is **terminal** (stop-the-line for that request: reported to the owner, never resent) or **curable** (the requester may resend with a fresh id on the same channel once the cause clears); never retried through another channel (owner 2026-10-26, OP5 B, `owner-decisions.md:67`). The class of `action-failed` is the owner's (OP10 A, `owner-decisions.md:72`); the class of every other code is **FROZEN (integrator, ADR 0055 [freeze])** (`decisions/0055-desk-verb-permission-tiers-02.md:117-122`, `:139-149`): terminal = `{sender, schema, hash, repo, policy}` (the request itself or its sender is wrong; a corrected request is a new request, and a terminal code is reported to the owner); curable = `{marker, order, stale-session, gate-missing, action-failed}` (a state outside the request that can clear). Producer: `delivery-desk` (`.out` `reason`); consumers: every requester (conductor, `delivery-run`, `ci-fix-loop`, `ticket-clerk`, `release-track`, `delivery-cleanup`), which look the class up in this table.

| Code | Class | Trigger |
|---|---|---|
| `sender` | terminal | transport sender is not in the desk-held registry for the run (B1); a conductor-only verb (B1) whose sender is not the registered conductor or whose `<id>` subtask is not `run`; any `<id>` with `<subtask>` `run` whose transport sender is not the registry's `run` id (`DEFAULT (integrator)`) |
| `schema` | terminal | the copy fails the closed per-verb schema: unknown verb, unknown or missing field, raw flag, force, string where an array is required, `id`/`verb`/`subtask` in the JSON (read from the hashed copy) differing from the line, including a relayed `claude -p` request whose `subtask` does not match the id |
| `hash` | terminal | the copy's sha256 differs from `sha256=<hex>` |
| `repo` | terminal | `repo` not under a registered clone; branch fails `<JIRA-KEY>(-[a-z0-9-]+)?`; `body_path`, `payload_path`, `record_path` or an attachment path outside its allowed root |
| `marker` | curable | a re-derived marker fails: head sha, `CODE-GATE-REVIEW`/`Verified-By`, H-pr approval, CI not green at `pr-merge`, `GATE-PASS` record missing for a `push` or `pr-create`, `branch-delete` content not merged into `merged_into` (never `DONE deleted=false`) |
| `order` | curable | a `pr-merge` predecessor is not merged |
| `policy` | terminal | a request the desk never grants (approve, trigger-prod, pipeline edit, `ci-rerun` on a non-flake class, force); a `tag-push` the repo profile does not allow (`DEFAULT (integrator)` forms, rows R40-1 and R4-J4, of the owner's N11 ruling "With no profile entry, tag-push is refused.": no `release_tags` entry, `release_tags.used` `"no"`, `tag` not matching `release_tags.pattern`, or a malformed entry, part A.2.2); a redaction hit in a body, payload or attachment |
| `stale-session` | curable | the GitHub or Atlassian session is not fresh (B3 step 7) |
| `gate-missing` | curable | `H1.ok` absent before `jira-create`; `H-prod.<step>.ok` absent before `publish`, or before a `tag-push` whose profile `release_tags.approval` is `human` (B4; `DEFAULT (integrator)`); `merge_reach` row absent before `pr-merge` |
| `action-failed` | curable | a valid request whose action then fails (non-fast-forward, branch protection, remote or `gh` error) (owner 2026-10-26, OP10 A, `owner-decisions.md:72`) |

## B3. Request file and the copy-and-hash step (M29)

Sender: (1) `desk-req.sh` writes `RUN_HOME/desk/<id>.req`, one JSON object `{"id", "verb", "subtask", "fields": {...}}` at 0600 under `umask 077` (`DEFAULT`: the envelope keys are carried so the desk can cross-check the line); (2) sha256; (3) one `DESK` line.

Desk, checks in this order; **the first failure wins** and names the one reason code (`DEFAULT (integrator)`; the place of the replay check, steps 1-4 and 9, is FROZEN (integrator, ADR 0055 [freeze], `decisions/0055-desk-verb-permission-tiers-02.md:185-191`)): (1) bind the sender from the transport and the `<id>` only (B1, conductor-only rule; an `<id>` with `<subtask>` `run` needs the registry's `run` sender) else `sender` (no `.out`); (2) repeat `<id>` with a stored `.out`: return it, stop (B2 idempotency, no hash compare); (3) copy to `$DELIVERY_ROOT/desk-inbox/<id>.req` (desk-owned, 0700; kept until the run is archived at CYCLE DONE); (4) hash the copy, else `hash`; (5) validate only the copy against B4, including the JSON `subtask` cross-check, else `schema`; (6) per-field checks (`repo`, branch, paths) else `repo`, redaction (B7) else `policy`, never-granted request (including a `tag-push` the profile `release_tags` entry does not allow, B4) else `policy`; (7) session freshness else `stale-session`; (8) gate files (B8; for `tag-push` only under `release_tags.approval: human`) and, for `pr-merge`, the `merge_reach` row (B5) else `gate-missing`; then `pr-merge` predecessors else `order`; then markers (B5) else `marker`; (9) `mkdir desk/<id>.inflight`, write `desk/<id>.inflight/target` (`<verb> <target>`, B2), act under the operator's auth, else `action-failed` (owner OP10 A); (10) write `RUN_HOME/desk/<id>.out` atomically at 0600, **also for `REJECTED`** except `sender`; (11) append one redacted JSON line per request and per result to `$DELIVERY_ROOT/desk-log/<run-id>.jsonl` (`DEFAULT` path); (12) reply.

No per-request account lock exists: R2-4 removed accounts (design errata: changelog B1 row still says "per-request account lock").

## B4. Verbs and request schemas (closed; no raw flags, no force, arrays not strings)

Field types (`DEFAULT (integrator)`): `repo` abs path (realpath under a registered clone); `branch` `^[A-Z][A-Z0-9]+-[0-9]+(-[a-z0-9-]+)?$`; `base`, `merged_into`, `ref` git ref name `^[A-Za-z0-9._/-]+$`; `pr`, `predecessors[]` int; `expect_head`, `sha`, `merge_sha` 40-hex (part A.1); `fields.subtask` (`pr-merge`: the PR's sub-task) `^(st[0-9]+|pm)$`; the envelope key `subtask` (B3) `^(st[0-9]+|pm|run)$` and equal to the `<id>` `<subtask>`, so a conductor `pr-merge` carries envelope `run` and `fields.subtask` `st<N>`; `*_path`, `paths[]` abs path under the root named in the per-field rules; `labels[]` array of `^[A-Za-z0-9._:-]+$`; `job` string `^[^[:cntrl:]]{1,200}$`; `ci_run_id` int; `tag` `^[A-Za-z0-9._/-]+$`; `package` npm name `^(@[a-z0-9-]+/)?[a-z0-9._-]+$`; `version` semver; `step_id` `^[a-z0-9-]+$`; `tool` enum `zephyr`; `dry_run` bool; `key`, `parent` `JIRA-KEY`; `to` enum D3 canonical status or `archive`; Jira `fields` map with keys from the allowlist below and string or string-array values. Every listed field is required (a missing one is `schema`) except `parent` on `jira-create`, which is present exactly when `fields.issuetype` is not `Epic` (an Epic with `parent`, or a non-Epic without it, is `schema`) (`DEFAULT (integrator)`). Unknown or mistyped field = `schema`. Requester: the skill that writes the `.req`; result reader: the skill that reads the `.out` (producer `desk-req.sh`, consumer `delivery-desk`).

| Verb | `fields` | Requester (phase) / result reader | Notes |

## B5. Marker re-derivation and the H-pr read-back (§6.3, R2-4, M6, M10, M16)

Before acting the desk re-derives (design §6.3; per-verb list FROZEN (integrator, ADR 0055 [freeze], `decisions/0055-desk-verb-permission-tiers-02.md:164-180`): `push` head, gate run; `pr-create` head, gate run, review record; `pr-merge` head, gate run, review record, H-pr, CI, order, `merge_reach`; `branch-delete` content-merged): **head** (`expect_head` equals the live branch head or PR `headRefOid`); **gate run** (`gate-runs/<expect_head>.md` exists for `push`, `pr-create` and `pr-merge`); **review record** at `record_path` (`record-<head>.md`, part A.6): line 1 `CODE-GATE-REVIEW: PASS head=<sha> blocking=0 medium=0`, line 3 `Verified-By: <seat-id> head=<sha>` whose `seat-id` differs from line 2's `Reviewed-By` seat, both with the landing head; **H-pr**: `gh pr view <n> --json reviewDecision,headRefOid,author,latestReviews` (or `gh api repos/<o>/<r>/pulls/<n>/reviews` for `commit_id`), holding only if `reviewDecision == APPROVED`, at least one review `state == APPROVED` by a human login other than the PR author and not `[bot]`, with `commit_id == headRefOid` (changelog assumption 12 is verified at the move); **CI** green on the landing head (the B6 `ci-status` aggregate `state` is `success` over the profile's `ci.required_checks[]`, part A.2.2); **order**: every predecessor PR merged; **`merge_reach`** row present in `repo-profile.md` (A.2.2; checked at B3 step 8, its absence is `gate-missing`, B2.1) (on Proof Web a merge reaches the production S3 backup upload, covered by the human approving review, R2-5); **content-merged** for `branch-delete` (`DEFAULT (integrator)` method): `git merge-base --is-ancestor <branch-head> <merged_into>` after a desk-side fetch, else every commit of the branch has a patch-id equal match in `git cherry <merged_into> <branch>` (no `+` lines), else (squash of 2+ commits) the branch's net diff `git diff <merge-base> <branch-head>` and the diff of one commit `S` on `<merged_into>` (`git diff S^ S`, `S` the request's `merge_sha`, which must equal line 2 of `RUN_HOME/merge-<merge_sha>.md`, part A.6, else `marker`) have equal `git patch-id --stable`; failure is `REJECTED marker`.

## B6. Result files and per-verb result schemas (M13; field names frozen here)

`RUN_HOME/desk/<id>.out`: one JSON object, atomic, 0600; authoritative for `claude -p` leads.

Envelope: `{"id", "verb", "status": "DONE|REJECTED", "reason": "<code>|null", "detail": "<one line>|null", "request_sha256", "sender", "utc"}`. Rules (`DEFAULT (integrator)`): `DONE` has `reason` and `detail` null; `REJECTED` has `reason` set and `detail` non-null; `request_sha256` is the hash of the desk copy, null when the reject precedes B3 step 4; `utc` is ISO UTC (part A.1). A failed action (B3 step 9) writes `status` `REJECTED`, `reason` `action-failed`, `detail` the remote or `gh` error line (redacted, B7) (owner 2026-10-26, OP10 A, `owner-decisions.md:72`); `.inflight` stays, so a later fresh-id resend of the same verb and target reconciles by read-back first (B2 duplicate-action guard, keyed on `<verb> <target>`, not the id).

**Result field types and required-ness (`DEFAULT (integrator)`):** on `DONE` every listed field is required and no other key is allowed (`additionalProperties: false`); on `REJECTED` only the envelope is present. Types: `pr`, `ci_run_id` int; `head`, `sha`, `merge_sha`, `headRefOid`, `commit_id` 40-hex; `url`, `comment_url`, `registry_url` and `attached[].url` https URL string; `*_path` and `attached[].path` abs path; `deleted`, `pushed`, `h_pr` bool; `key` `JIRA-KEY`; `parent` `JIRA-KEY` or null (an epic has none); `tag`, `ref`, `package`, `version`, `author`, `login`, `name` string per B4; `merge_reach` string (the profile row verbatim); `fields` object (key -> string or string array, B4 readable set); `read_back` object: `jira-update` the updated fields (as `fields`), `jira-transition` `{"status": <Jira status string>}`; arrays are always present, possibly `[]`, never null.

## B7. Redaction before storing (M28, M31)

- **Pattern source:** `secrets.pattern_file` in `repo-profile.md`.
- **Desk side:** every `body_path`, `payload_path` and `ci-logs` output is `grep -E`-scanned by the desk itself before use or storage; **a hit refuses the request with `policy`, never masks** (`DEFAULT`: refusing keeps the rule mechanical). Every string field of a request is scanned too. Traces and other text attachments are scanned; images are attached unscanned and labelled as such (owner 2026-10-26, OP9 A, `owner-decisions.md:71`). The label is the `pr-comment` stating they are unscanned screenshots, and attachments come only from `RUN_HOME/<subtask>/lanes/` (`DEFAULT (integrator)`).
- **Agent side:** `pre-pr-gate` step 4 scans diff, logs and PR body (card 10).
- **Logs:** every logged request and result is redacted before it is appended to `desk-log/`.
- **Modes:** `DELIVERY_ROOT` under `umask 077`; `.out` 0600; `desk-inbox/` 0700.

## B8. Human gate files the desk writes (M30, §5.0)

The human types one line in the desk session (`DEFAULT (integrator)`: a typed line, not a `SendMessage` verb, because the human is not an agent). Producer: the human; consumer: `delivery-desk`. Exact grammar:

```
GATE   <run-id> <gate> <verdict> <text>     ^GATE ([a-z0-9-]+) (H0|H1|H-e2e\.(st[0-9]+|pm)|H-pr|H-prod\.[a-z0-9-]+) (ok|changes|reject)( .+)?$
ANSWER <run-id> <subtask> <unit> <text>     ^ANSWER ([a-z0-9-]+) (st[0-9]+|pm) ([ui][0-9]+) (.+)$
REBIND <run-id> <sender-id>                 ^REBIND ([a-z0-9-]+) ([^ ]+)$
```

Gate x verdict matrix (`DEFAULT (integrator)`: any other pair is refused in the desk session, nothing written): `H0` ok; `H1` ok, changes, reject; `H-e2e.<subtask>` ok; `H-prod.<step_id>` ok; `H-pr` none (external evidence only, B5). The `<run-id>` resolves `RUN_HOME`. The desk writes the file named in part A.2.1 with `utc=`, `by=` (OS login of the desk session), `ref=` (computed per A.2.1; a leading `ref=<value>` token in `<text>` overrides it, used for `jira:<KEY>@<comment-id>`), `text=`; for `H1 changes` and `H1 reject` it also writes `<text>` to `RUN_HOME/gates/H1.notes.md`, after renaming any earlier H1 files (part A.2.1). `ANSWER` is written into `RUN_HOME/<subtask>/inbox/` (part C5.1).

| Gate | Evidence | Desk enforcement |
|---|---|---|
| H0 | `RUN_HOME/gates/H0.ok` | none (the conductor waits for the file) |
| H1 | `H1.ok` / `H1.changes` / `H1.reject` (a Jira-side approval is typed as `GATE <run-id> H1 ok ref=jira:<KEY>@<comment-id> ...`) | only `H1.ok` unlocks `jira-create` |
| H-e2e | `RUN_HOME/<subtask>/gates/H-e2e.<subtask>.ok` | written by the desk; enforced by the lead before generation (part A.2.1) |
| H-pr | external: the approving review (B5) | `pr-merge` refuses without it |
| H-prod | `RUN_HOME/gates/H-prod.<step_id>.ok` (FROZEN (integrator, ADR 0055 [freeze], `decisions/0055-desk-verb-permission-tiers-02.md:201-202`)) | `publish` refuses without the step's file; so does a `tag-push` under `release_tags.approval: human` (B4; `DEFAULT (integrator)`) |

`RUN_HOME/gates/` holds run-level gates; `RUN_HOME/<subtask>/gates/` holds the sub-task's H-e2e file; `state.md` points at both.
