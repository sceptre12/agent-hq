## 0. Owner summary (15 lines)

1. The family encodes the owner's process: grill, architecture, human acceptance, dispatch plan, run with up to 30 agents per sub-task, pre-PR gate, CI fix loop, post-merge testing, release tracking, cleanup. Fifteen new skills, five extensions, the rest reused.
2. Every git, GitHub and Jira action goes through one new skill, `delivery-desk`, run by the desk session under the operator's own locally configured GitHub and Jira auth (R2-4; no bot account, no approved-account list): request copied and hashed by the desk, closed per-verb schema, independent re-verification of markers, `DONE`/`REJECTED` reply (D3). The transport is a new `DESK` verb added to the permission-tiers-02 §2 grammar by an ADR amendment (T1; W0 item 3b), which also clears B2 of round 1.
3. The architecture gate is human acceptance by whoever is executing the workflow (D1, D18); the artifact is still reviewed first, and a sub-task whose fix loop still has open Blocking/Medium findings after round 3 stops and hands those findings to the human while other sub-tasks continue (D7).
4. One PR per sub-task; the human reviews alongside the agents; after a human approving review the agents merge via the desk skill in architecture-plan order (D5). On <pilot-app> a merge runs the merge pipeline through the production S3 backup upload; that approval covers it, and live production stays the human Zephyr promotion (R2-5, §1 stage 5b).
5. Concurrency: 30 agents per sub-task, 200 machine-wide (D4), always full width (D20). Claude Code caps a session at 20 concurrent subagents and nests to depth 3 by default (measured), so each sub-task runs in its own session with `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS=30`, and the ledger counts tree-wide including `claude -p` processes (§4 (part-03-personas-and-concurrency.md)).
6. Two dispatch backends are built now (D25): the Agent tool inside a session and `claude -p` for spawning sub-task sessions. `claude -p` has no sandbox or deny list; §6.4 (part-05-execution-constraints.md) specifies a scrubbed-environment launcher with fail-closed tool flags (M28); it is untested until the work environment.
7. E2E tests are mandatory for user-visible stories where the repo has a harness and are written with the NLTA plugin: Gherkin `.feature` intent, human Gherkin checkpoint, generated Playwright/WDIO TypeScript, reviewed like code, with mock code excluded from `dist/` by `fileReplacements` plus `IgnorePlugin` and a dist scan at the pre-PR gate (D17, §3.6 (part-03-personas-and-concurrency.md)).
8. Jira is the only tracker; every Jira read or write is a desk step; clerk cadence at loop hand-back or about every 30 minutes (D11, D62).
9. Learnings go to the Hermes port inside `agent-hq` through its API door once the owner turns it on; until then captures queue under `RUN_HOME/capture/` (D19).
10. Full-breadth MVP: everything is built before the pilot; `delivery-shepherd`, `ci-fix-loop` and `release-track` ship as marked pilot drafts whose provenance is `pending pilot` (D14, M31, clears B3).
11. Build waves W0-W3 happen in `agent-hq` and end at "ready to move"; the owner moves and installs; pilot and hardening waves P1-P2 happen in the work environment on <pilot-app> (owner no-symlink rule). The build runs under its own 50-agent cap across the Worker1, Worker2 and desk sessions (B-1); that cap and the build machine's ledger are not the work runtime's 30/200 ledger.
12. Build time: about 12 hours of wall-clock elapsed time (range 10-14 h) for W0-W3 to "ready to move" with up to 50 agents in parallel (B-1, B-4: maximum safe parallelism under the 50 cap, no cost metric), plus explicit owner waits (ADR ratifications, the move) that are not counted. Pilot numbers replace these.
13. Smaller reviewer sets than 7 are allowed only after a RACI remap and a 3-seat probe show no lost checks (D12, clears B4); until then every `pr-review` runs 7 seats.
14. Adopted as skill rules: D35, D55, D57, D59, D60, D62. Advisory only, never written as rules: D44, D54, D58, D61, D66 (D6).
15. What the owner still has to do: launch the sub-task sessions or approve the `claude -p` spawner in the work environment, run `/nlta:bootstrap` interactively where a repo has no e2e workspace, answer the Gherkin checkpoints, approve PRs, run production steps (D15), turn on the Hermes port, ratify the `DESK` ADR amendment (T1), set `DELIVERY_ROOT` and the subagent cap at the move, and keep the Zephyr MCP they already have configured locally (R2-1; the design installs nothing).

**Stop-the-line (Rule 4 plus retro G1-G5):** classifier or harness block; a failed gate; authoring on main; a spawn without a free slot; a verifier who authored the code; two writers on one `substate.md`; any unrecorded production write; a build or publish from the main checkout (G1); a release step before its simulation (G3); hooks skipped without a recorded hook or affected-gate pass (G4, D21); fix commits left unpushed (G5); any edit to a pipeline definition by an agent (D23). The lead halts affected units, writes state, reports; clearing needs a fresh human grant. **Not stop-the-line:** a built-in safety-check denial on a seat's own probe is not a classifier block; the seat drops that probe, notes it, and continues (G52 `RLM:106`).

**Back-edges:** stage 5, 5a or 6 failure becomes a new unit and re-enters stage 4 for that unit. A CHANGES verdict re-enters stage 2 with the human's notes binding. A unit finding an architecture contradiction posts the C2 record with `verdict: ESCALATE`, `reason: arch`, which the lead writes to `escalations/<unit>.md` (INTERFACES C2); the lead pauses only the affected units. Failure class sets the response: Cosmetic fixes in branch; Structural holds unfixed branches of the wave and repairs the spec; Systemic pauses dependent work and repairs the contract. Re-entry map: source-logic failure re-enters review then CI-parity; CI or packaging failure re-enters CI-parity; consumer-environment defect fixes the profile and re-runs only the simulation.

**Two exits (M32).** CLEANUP DONE, at the end of 5c per sub-task: every catalog row the sub-task's build created is `released`, PR open or merged, worktrees gone. CYCLE DONE, at the exit of stage 8 for the run: every stage PASS with artifact; fix counters 0; stage 6 and 7 worktrees released in the second cleanup pass; retro filed, placeholder grep clean; the execution counter is the stage 8 `execution-log.md` row; sessions and buses ended. Archiving artifacts out of volatile temp and restoring the `repo-profile.md` per-ticket fields to `FILL_IN_BEFORE_DISPATCH` are human steps named in the conductor's final status post (no restore mode or archive target is named yet; erratum E33, AM-4 W2-6).
