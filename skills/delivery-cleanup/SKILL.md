---
name: delivery-cleanup
description: Remove only the resources a delivery run registered in catalog.tsv, after a sub-task merges, after post-merge verify (pm), or when a run is abandoned (stage: stopped). Use when the lead receives MERGED, when the pm lead sees RELEASE LIVE or ROLLED-BACK, or when the conductor finishes every sub-task before stage done. Runs a read-only dry run, an approved explicit list, a separate executor that re-measures and deletes by literal path, and a validator spot-check; releases port rows with their registry claims; deletes branches only when content-merged (D8).
version: 0.1.1
---

## Trigger
Use when: inbox `MERGED <subtask> <merge_sha>` arrives (mode `subtask`); the `pm` lead reads `release-<pm_sha>.md` line 1 `RELEASE: LIVE` or `RELEASE: ROLLED-BACK` (mode `subtask`, `SUBTASK=pm`); the conductor sees every `subtasks[]` entry `cleaned`, before `stage: done` (mode `final`); or the run is abandoned, `state.md` `stage: stopped` (mode `final`, no `MERGE_RECORD`). The scope is catalog rows only (D9). Never use it to tidy anything the catalog does not list.

Paths: A.2, A.2.2, A.5, A.5.1, A.5.2, A.6 are in `architecture/delivery-workflow/interfaces/part-a-state.md`; B1, B2.1, B3, B4, B5, B6 in `part-b-desk.md`; C2, C5.1, C7 in `part-c-waves-control.md`; D1, D2.2 in `part-d-enums-topics.md`. Scripts: `tools/delivery/catalog.sh`, `tools/delivery/desk-req.sh`, `~/projects/agent-hq/tools/port-check.sh` (as `skills/port-claim/SKILL.md` cites it).

## Steps
0. **Step 0, inputs.** Validate `RUN_HOME` (absolute, exists, last segment `^[a-z0-9-]+$`, which is the run-id; `catalog.sh` exits 2 otherwise), `MODE` (`subtask|final`), `SUBTASK` (required and `^(st[0-9]+|pm)$` for `subtask`; omitted for `final`), `MERGE_RECORD` (`st<N>` only: path of `merge-<sha>.md`, four lines `pr=`, `merge_sha=`, `method=`, `merge_reach=`). Evidence per C5.1 in the `MERGE_RECORD` slot (D2.2 row 9): `pm` needs `postmerge-<pm_sha>.md` and `release-<pm_sha>.md` with line 1 terminal (paths from the `pm` `substate.md` `postmerge_record`, `release_record`, A.2), or, before a second `pm` lead on a post-merge re-entry, the `postmerge-<pm_sha>.md` whose line 1 is `POSTMERGE: FAIL` (A.8 merge order and `pm` host, AM-5 29-19); `final` needs a `cleanup-<run-id>-<subtask>.md` with line 1 `CLEANUP DONE <subtask>` for every `subtasks[]` entry, or `state.md` `stage: stopped`. Missing evidence is `INPUT-ERROR MERGE_RECORD missing`; a non-terminal `release-` line 1 is `INPUT-ERROR MERGE_RECORD format`. `DELIVERY_ROOT` (env, required by `desk-req.sh`): set, `^/[^[:space:]]+$`, and `RUN_HOME` equals `$DELIVERY_ROOT/<run-id>` (reasons `unset`, `format`, `path`). `WORKTREE_BASE`: the `worktree_base` field of the profile `state.md` `repo_profile` links (`<abs path>@<sha>`, A.2); when set, pass it inline to every `catalog.sh` call; unset or empty, omit it (then `RUN_HOME` is the only legal root). A bad field prints `INPUT-ERROR <NAME> <reason>` (reason `missing|enum|path|unset|format`, D1: `missing` absent or no file, `enum` outside its set, `format` fails its pattern, `path` not absolute, absent, or not `$DELIVERY_ROOT/<run-id>`, `unset` an env var not set), one line per failing field, then stop; no retry, no prompt.
1. **Audit.** The host session (the approver of Step 3) runs `RUN_HOME=$RUN_HOME WORKTREE_BASE=$WORKTREE_BASE catalog.sh audit` (drop `WORKTREE_BASE=` when unset). `GHOST` and `SQUATTER` lines go into the dry run as findings; lines for rows outside this pass's scope are reported only. Do not fix by hand. Exit 5 (`lsof` missing or failing; the script names each row on stderr) gives no verdict for those `port` rows: carry them into the dry run as `no-audit-verdict`, never read the missing line as `MATCH` or `GHOST`; the executor's own `lsof` re-test (Step 4) still decides each of them (A.8 A.5, AM-5 PR10-M4). Exit 2 or 4 is a stop and a report.
2. **Dry run (read-only).** The same host session reads `catalog.tsv` (latest row per `kind`+`handle`). Scope: mode `subtask` takes the rows whose `subtask` column is `SUBTASK` (the `pm` rows belong to the `pm` pass only); mode `final` takes every row still `planned`, `live` or `failed`, any `subtask` value including `run`. Build the table per `references/dry-run-table.md`: one row per `planned`, `live` or `failed` row, `kept` rows carried as already kept, `released` skipped; bytes by `du -sk`, files by `find <path> -type f | wc -l`, `.git` included and stated. Evaluate every guard of `references/executor-rules.md` that needs no desk or host tool. List non-catalog finds (sources in the table reference); they go to `## residual` and are never deleted (D9). Nothing is changed in this step.
3. **Approval.** The approver (the sub-task lead for `st<N>`, the `pm` lead for `pm`, the conductor for `final`; C5.1) writes an explicit list of row ids with `delete`, `release` or `keep <reason>`. No pattern, no "all", no force path. A row whose guard fails is `keep` with a reason.
4. **Execute.** The approver dispatches a separate mechanical-tier `cleanup-executor` (persona brief `skills/delivery-run/references/briefs/cleanup-executor.md`), passing the `## dry-run` table and the `## approved` list verbatim; the executor copies both into the temp record first (`references/cleanup-record.md`). It re-measures every approved path; a bytes or file-count basis that differs from the dry run is a stop (report, no workaround). It applies the cleanup column of A.5.1 per kind by citation, with the guards, already-gone rules and order of `references/executor-rules.md`: one `rm` per literal path, `kill -0` before and after every pid, a `port` row released by repeating its claim as `released` via `port-check.sh --claim` after its listener stops (a refused claim is kept and flagged, never `--force`), then `catalog.sh release`. It appends each command to `## executed`. A failed guard is `catalog.sh keep <kind> <handle> <reason>` and a line in `## residual`, never a workaround. A classifier or permission block is a stop: report it, never wrap or reroute it.
5. **Host hand-off and branches.** Desk verbs (`fetch`, `branch-delete`) and host-session tools (`CronDelete`, `TaskStop`) go through the hand-off in `references/executor-rules.md`: the executor writes requests and returns them, the host session sends or performs them and re-dispatches the executor with the results. Branches are gated by D8, local and remote: the B5 content-merged test (ancestor, `git cherry` per-commit patch-id, squash patch-id) runs against the profile `default_branch` (A.2.2) `sha` a desk `fetch` returned; the remote goes first by desk `branch-delete`, the local ref only after its `DONE`. Empty `merge_sha` (always so for `pm` and `run` rows, A.2), a no-reply or any `REJECTED` keeps the row and flags it (B1, B2.1; `marker` without resend, spec §4). A repo with no remote (`merge_reach: local`) gets local-only branch deletion: no desk `fetch` or `branch-delete`, and the record says "no remote" (A.8 A.5.1, AM-5 19-F6; `references/executor-rules.md`).
6. **Record (temp).** When Steps 4-5 are complete, the executor, the record's writer (A.6), completes `## residual` of `RUN_HOME/cleanup-<run-id>-<subtask|final>.md.tmp` per `references/cleanup-record.md`.
7. **Spot-check.** A different agent, persona `validator`, never the executor or the approver, re-tests every path in `## executed` (`test -e` false, `kill -0` fails, `git worktree list` lacks it, ref gone, `lsof` shows no listener) and runs the catalog checks: `catalog.sh list --live --subtask <st>` shows 0 build resources (mode `final`: `list --live` shows none), and no row of the scope is latest `planned`, `live` or `failed` in `catalog.tsv` (`list --live` prints the latest row of every pair that is `planned` or `live`, INTERFACES script table; `failed` is never listed, so read `catalog.tsv`). It appends its block, ending `SPOT-CHECK PASS` or `SPOT-CHECK FAIL <n>`, to `## residual` of the temp record.
8. **Finalize.** On the validator's `SPOT-CHECK PASS` the executor, without re-checking, inserts line 1 `CLEANUP DONE st<N>|pm|final` at the top of the same `.md.tmp` as its last write and `mv`s it onto the final name (one temp file, A.6). Otherwise no final file appears and the approver sends C2 `ESCALATE` reason `human-step` with the `.tmp` path (OQ-A). Send nothing else; the conductor reads line 1 of the record. A resumed or re-run cleanup restarts at Step 1.

Never touched: ledger and records (`state.md`, `substate.md`, `catalog.tsv` except through `catalog.sh`, `merge-*`, `review/` (except the `bus/` `data_dir` of a catalog `bus` row for an in-run review bus, `review/<subtask>/<review-id>/bus/`, A.1, D5, AM-5 10-B2), `gates/`, `cleanup-*` other than the executor's own record files, A.6; under `desk/` only new `.req` files written by `desk-req.sh` and the host's B1 `.req.noreply` rename, as the spec §4 Branch-delete row has the executor write the `.req`), `RUN_HOME/<subtask>/security-audit/run-<N>/` (a run record, A.5.3; the plane is archived at CYCLE DONE), other sessions' worktrees, open PR branches, credentials. A process or tmpdir a security-audit agent registered is a normal catalog row.

## Red flags
| Thought | Do instead |
|---|---|
| "This tmp dir looks like ours, delete it" | Not in `catalog.tsv`: report in `## residual`, never delete (D9). |
| "Branch is merged by ancestor check only" | Ancestor OR `git cherry` / patch-id equality OR the squash patch-id (B5), against the fetched `default_branch`; squash merges fail ancestor. Else keep and flag (D8). |
| "Remote branch delete is safe, only the local needs the check" | Local and remote are both gated; remote goes through desk `branch-delete`, never `git push`. |
| "Worktree or clone has a few ignored files, remove anyway" | Any output from `git status --ignored --porcelain` (an ignored `.env`, a dirty file) fails the guard for a worktree and a clone alike: keep, report in `## residual`. This skill moves or copies nothing. |
| "Kill it by name, the pid changed" | Only by the pid in a catalog row, `kill -0` before and after. Never by name or pattern. |
| "Free the port in `ports.tsv` by hand" | Stop the listener, repeat the claim row as `released` with every field quoted, then `catalog.sh release`. |
| "The claim was refused, add `--force`" | Never `--force` in a delivery run: keep the port row, flag it, stop for that row. |
| "Audit says GHOST, just release the row" | Only for kinds with no residue; `port`, `bus` and `branch` still need their claim, `pm2 delete`/`rm`, or the D8 remote gate. |
| "Counts differ slightly, continue" | Count-basis mismatch is a stop. |
| "The executor can approve and check itself" | Approver, executor and validator are three different agents. |
| "Tag, container, image, workspace: delete it" | No delete verb exists; `kept` and reported (A.5.1). |
| "The pm worktree has no PR, so it always passes" | It passes only the PR condition (OQ-B); a dirty tree or an ignored file still keeps it. |
| "Abandoned run, clear every branch" | `stage: stopped`: unmerged branches and their worktrees are `kept` and flagged; processes, ports, leases, buses, temp dirs are released. |
| "Desk said REJECTED, try `git push --delete` instead" | Keep and flag; never another channel (B2.1). |

## Exit criteria
- [ ] `list --live --subtask <st>` shows 0 build resources; no row of the scope is latest `planned`, `live` or `failed`; every row is `released` or `kept` with a reason.
- [ ] The record's first line matches `^CLEANUP DONE (st[0-9]+|pm|final)$` and the four sections follow in order.
- [ ] The `validator` spot-check passed and is written in `## residual`; non-catalog finds are listed there, untouched.
- [ ] Every deleted branch was content-merged into the profile `default_branch`; every other branch is `kept` with a flag.
- [ ] Second pass done: mode `subtask` for `pm` after `RELEASE: LIVE|ROLLED-BACK`; mode `final` for the run (also when `stage: stopped`). The stage 6 and 7 (`pm`) worktree passes the A.5.1 PR condition without a PR (owner-accepted answer to OQ-B; INTERFACES 1.5.0 A.8 A.5.1, AM-5 19; design M32) and is released when it is clean with no ignored file.
- [ ] No ledger, record, other-session worktree, open PR branch or credential was touched.
