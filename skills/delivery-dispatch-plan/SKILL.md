name: delivery-dispatch-plan
version: 0.2.0
description: Turns an accepted architecture.md plus drafts and the repo profile into an executable dispatch plan - sub-tasks, units, DAG, lanes, shared-file owners, port table, slot plan, verification - then dispatches the Plan-checker and loops to PLAN-CHECK clean or round 3. Use when an accepted architecture must become an executable dispatch plan (delivery stage 3), or when a post-merge failure adds new units for a new sub-task (NEW_UNITS).
---

## Trigger
Use when an accepted architecture must become an executable dispatch plan: sub-tasks, units, DAG, lanes, shared-file owners, slot plan, verification. Stage 3 has no human gate (Rule 11): the human is informed, the Plan-checker and the review loop are the bar.

## Steps
0. **Step 0, validate inputs.** `DELIVERY_ROOT` is an environment variable; the rest are `NAME=value` arguments. Print one line per failing field, then stop; no retry, no prompt (INTERFACES D1).
   - `DELIVERY_ROOT` unset: `INPUT-ERROR DELIVERY_ROOT unset`.
   - `RUN_HOME` (path under `$DELIVERY_ROOT` that holds `state.md`), `PLANS_DIR` (path that holds `architecture.md` and `drafts/`), `REPO_PROFILE` (`<abs path>@<40-hex sha>`, the file exists): `INPUT-ERROR <NAME> missing|path|format`.
   - `NEW_UNITS` (optional): when set it must equal `RUN_HOME/pm/new-units.md`, else `INPUT-ERROR NEW_UNITS path`. Set means post-merge re-entry (step 13).
   - `state.md` must give `interfaces_version`; absent is `INPUT-ERROR interfaces_version missing`.
   - Read `RUN_HOME/tickets.tsv` (latest row per `slug` governs; no row yet means the draft slug stands in). A ticket field the plan needs (`summary`, `status`) comes from `jira-get` `{key, fields[]}` through the conductor relay (INTERFACES 1.8.0 AM-8 V6): write the fields file, run `tools/delivery/desk-req.sh <run-id> run jira-get <file>`, hand the printed `DESK` line to the conductor to send, and read `RUN_HOME/desk/<id>.out` (B1). A `REJECTED` is reported, never sent another way.
   - Profile keys this skill reads: `ports.bus_base`, `ports.lane_base`, `durations.unit_median_min`, `durations.pr_review_min`, `gates.*`, `worktree_base`, `clones[]`, `linked_profiles[]`, `e2e.harness` (`nlta|none`) (INTERFACES A.2.2; AM-5 17). An absent A.2.2 key fails Step 0 as `INPUT-ERROR <key> missing` (A.2.2), except `ports.bus_base` and `ports.lane_base`: absent, the port rows carry `FILL_IN_BEFORE_DISPATCH`, which fails step 11 (A.2.2 `ports.*` row). Never guess a value.
1. **Read and measure.** Read `architecture.md` (merge order, contracts, test plan hooks, the one required header line `security_sensitive: yes|no`, INTERFACES A.2, owner OQ-1), `drafts/index.md` and every draft. Any repo fact the plan relies on (paths, globs, manifests, scripts, existing ports) is verified by a command whose result you record as `measured: <cmd -> result>`. A claim you cannot measure is written as "unmeasured, verify at move". If a measurement contradicts a frozen architecture fact, stop (Red flags) and re-measure before anything else.
2. **Cut sub-tasks.** One PR each (D5), in the merge order `architecture.md` gives. `st0` is the plan PR: it commits `plans/<epic>/*`, `contracts/` and `.tasks/`, first in merge order, with those globs in the owner table. The sub-task table's `merge order` column is binding: the conductor's merge predecessors are every sub-task with a lower `merge order`, while `RELEASE` follows depends-on (INTERFACES A.8, 29-18). Each later cut is either dependency-free with computed disjoint globs or strictly ordered (successor starts only after `RELEASE`). Each sub-task row carries `ticket`, `branch` (`<key>-<slug>`), `repo`, lead backend, depends-on, and the version-bump list of affected apps under `apps/`. Details: `references/unit-and-waves.md`.
3. **Define units.** Ids `u<N>`. Each unit has exactly one `done_condition` `{token, command}` that a verifier can run, scope globs, blocked-by, persona and tier, lane, e2e `new|updated|none`, a budget in minutes taken from the profile's measured medians, and its `ticket` (from `tickets.tsv`). A unit with no runnable verifier is a stop row. Never invent an effort figure.
4. **Write the unit task files.** One `.tasks/<unit>-<slug>.md` per unit at the primary repo root, using `writing-plans` for the content and the 11-section layout and six pre-flight checks of `part-04` section 5.3b by reference (template: `references/templates/`). Scope globs go under heading `## 3`, one `- <glob>` per line (git `:(glob)` dialect). Do not write into `references/templates/`.
5. **Shared-file owner and serial-lane table (M16).** For every package manifest, lockfile, barrel, generated file and CI config name one owning unit; every other unit that touches it is serialized behind the owner or rejected. Also name the one owning document of every cross-unit contract (D63). Overlapping globs or an implicit touch reject the plan. Procedure: `references/shared-files-and-parallelism.md`.
6. **Blockers and DAG.** `blocked-by` becomes `depends_on` edges (same wave, acyclic, rule 15). For each blocker unit `u<M>`, place its Integrator item `i<M>` in the same wave as its dependents, and each dependent `depends_on` `i<M>`, not `u<M>` (the S4a engine step, INTERFACES 1.8.0 AM-8 V13; `references/unit-and-waves.md`). A cross-wave dependency is expressed by wave order (the barrier), never an edge. Add an edge only for a real data or file dependency; a false edge serializes work (the D55 finding). Sketch the frontiers.
7. **Personas, tiers and e2e.** Choose each unit's `persona` from the closed set (INTERFACES D2.1) and `tier` (`design|execute|verify|mechanical`, never a model name). Add e2e units per user-visible story by the method in design section 3.6; where `e2e.harness` is `none` the plan names the gap and points to the test plan's by-hand coverage. From test-plan v0, write into `PLANS_DIR/test-plan.md` the §A3 e2e rows (one per e2e unit) and the batched `.feature` list (the paths those units write); this skill is their writer at stage 3 (INTERFACES 1.8.0 AM-8 V12). The desk H-e2e hash and `post-merge-verify` read them.
8. **Lanes and ports.** Write the lane table with a per-lane resource profile: HTTP, HMR and devtools ports, browser pre-staged by the desk `INSTALL`, device lanes human-run. Write the port table, one candidate per bind as `<base> + 20*k` with `k` in the row (INTERFACES 1.5.0 A.5.2, AM-4 W2-3), from `ports.bus_base` and `ports.lane_base`: `bus` rows per build-mode sub-task, `review-bus` rows per sub-task that runs `pre-pr-gate` (`st0` included, no `bus` row for `st0`; `pm` gets none from this plan), and lane rows once per lane for the run, `k` the per-bind index, consecutive in table order from 0 (A.5.2 "lane binds by consecutive bind index"; fixed app ports keep their app port, outside the formula) (`references/shared-files-and-parallelism.md` section 3). Every candidate and every candidate + 10, fixed app ports included, is pairwise distinct and at most 65535, so the one +10 retry lands on an odd ten no candidate uses (W2-3). The plan states that the launcher claims each candidate per A.5.2 before launch, never auto-picks, makes exactly one retry at candidate + 10 after a refusal (claimed before bind), and stops the line on a second refusal (a lane maps to `lane-unavailable`) (INTERFACES 1.5.0 A.5.2; AM-3, owner OQ-2); `port-check.sh` exit 3 (registry unusable) stops the line with no retry (A.5.2); and that no plan value is promised free. The plan itself runs no `port-check.sh`.
9. **Slot plan, budgets and the Rule 7 note.** Per build-mode sub-task state `dispatch_budget` (rule 11 total of the bundle) and peak concurrency; the machine line counts, per concurrently building sub-task, its peak plus `sum(reserved)` (A.3 seed `reserved`, A.4), summed against 200, and holds concurrent builds to 3 (rule 8). State that full-mode `security-auditor` agents draw on free slots at launch (A.4), 0 pre-allocated, counted in the ledger; the plan header carries `security_sensitive:` copied from `architecture.md`, and when `yes` each sub-task names the `pre-pr-gate` row `C26` (`validate-findings.cjs`). The audit is not a unit. Then write the computed Rule 7 note. Arithmetic: `references/shared-files-and-parallelism.md`.
10. **Write the artifacts.** `dispatch-plan.md` (header with `interfaces_version: <version>@<sha256>` copied from `state.md`, never edited by the conductor afterwards), per build-mode sub-task (`st0` and `pm` have no seed and no waves, A.2 modes) `subtasks/<subtask>/substate.seed.md` (exactly the keys `subtask_id session_id reserved frontier interfaces_version phase: seeded`), `subtasks/<subtask>/bundle.md` (the bundle header) and `subtasks/<subtask>/waves/` (`01-build.md`, `02-integrate.md`; waves numbered from 1), plus `subtasks/<subtask>/constitution.md` (bundle root, not under `waves/`) only when the repo has no profile yet (C1; "no profile yet" = `repo-profile.md` absent or `FILL_IN_BEFORE_DISPATCH` in a required A.2.2 key, INTERFACES A.8, AM-5 17; this skill is its only writer, at plan time, never at run time, A.8 A.6 and C8, owner S4b; not a wave file; the lead runs it before `01-build.md` and verifies its record as a C2 `PASS`), the `.tasks` files, and an empty `RUN_HOME/catalog.tsv` (create it empty; only `catalog.sh` appends). Wave files, bundle fields and `Brief:` lines: `references/unit-and-waves.md`. `max_concurrent` is not a field of the spec; it is a caller argument of `delivery-run`.
11. **Pre-dispatch checklist.** Run every row of `references/predispatch-checklist.md`: sentinels gone, every path `ls`-verified, flags present, six unit pre-flight checks, port candidates distinct. Fix every failure before step 12, except two that stop the skill: a port-candidate clash (checklist row 8) stops and reports, never re-picks a port; and a sentinel this skill cannot fill (a profile value, such as a `FILL_IN_BEFORE_DISPATCH` for an absent `ports.*` key) stops the skill with the missing key named, and the plan goes back to intake; never guess a value.
12. **Plan-check, review, loop.** Plan-checker first, before round 1 (D55): `references/plan-check-loop.md` (G48 check before round 1 and after every fix, fresh checker per round, stop at `clean` or round 3). Then call `review-tailor` with every INTERFACES D2.2 row 4 input: `RUN_HOME`, `SLUG=run-plan-<n>` (`n` a per-run counter you mint), `ARTIFACTS` (the plan files this skill wrote: `dispatch-plan.md`, each `bundle.md` and `waves/` file, the `.tasks` files), `KIND=plan`, `STAKES`, `CONTENTION`, `NOVELTY` (the values `delivery-architecture` chose for its own `review-tailor` call, read from the three `key: value` lines of the fixed header block of `PLANS_DIR/review-architecture.md`, lines 2-4: the D2.2 row 3 output is the row 5 input, INTERFACES D8 and C8, AM-5 17 and 15; copied into the plan, never re-chosen; a value absent there is `INPUT-ERROR <NAME> missing`; enums in `skills/review-tailor/references/step0-inputs.md` rows 6-8), `SECURITY_AUDIT` (from `state.md` `security_audit`), `ORCHESTRATOR_TIER` (from `state.md` `orchestrator_tier`, AM-3 errata (g)); run the `RUNG:` it returns (its plan rule is card 5: 2b above 10 units, else 1; `review-tailor` rung-rules). Review loops stop after round 3 and the owner decides (owner D7); the plan's review section then carries `PLAN-REVIEW: STOP round-3` (INTERFACES 1.6.0 AM-6 (g)). After every fix (Plan-check or review), run the G48 check on the plan files (`part-03` G48) and re-run step 11; a fix that changes `waves/` or the unit table also gets a fresh Plan-checker inside that round, and when that checker finds problems the round's fixer fixes them in the same round (`references/plan-check-loop.md`).
13. **Post-merge re-entry.** With `NEW_UNITS` set, read the new-unit lines and take the sub-task id `st<N>` the conductor added to `state.md`, then produce every step-10 output for `st<N>` only (A.2 post-merge re-entry and INTERFACES A.8, AM-5 17; the full list below is spec §8's; the conductor launches `st<N>` only once the plan has its row and `plan-check.md` line 1 is `PLAN-CHECK: clean` and newer than `pm/new-units.md`, A.8 29-29): run step 3 on the new-unit lines (each becomes a unit with a runnable `done_condition`, else a stop row), unit-table rows (tickets from `tickets.tsv`), step 5 (owner-table check of the new scopes against the existing ones), step 6 (`depends_on` edges in the new `01-build.md`), step 7 (persona, tier and e2e of the new units), step 8 for new lanes (new lane-table rows and their lane-port rows appended to the run-wide tables, `k` continuing from the last existing bind index; existing lane rows are reused, never edited), `.tasks` files, seed, `bundle.md`, `waves/`, the port-table `bus` (`k = 2N`) and `review-bus` (`k = 2N + 1`) rows, step 9 for `st<N>` (`dispatch_budget`, peak, and the machine line re-summed against 200 with `st<N>` included), and the `st<N>` sub-task row appended to `dispatch-plan.md`; then step 11 and the step 12 loop, ending in a fresh `plan-check.md`. Existing sub-tasks' rows and files are not edited, in the step-12 fix loop too: a fix edits only `st<N>`'s files, the rows appended to `dispatch-plan.md` (including appended lane rows) and its machine line. A fix that would need an existing sub-task's files stops the skill with a report to the conductor.
14. **Finish.** Print the path of `dispatch-plan.md`, the line-1 token of `plan-check.md`, the units and sub-task counts, and the Rule 7 note headline. No gate: the conductor informs the human.

## Red flags
| Rationalization | What to do instead |
|---|---|
| "The globs overlap a little, the units will not conflict in practice." | Overlap or an implicit touch rejects the plan (M16). Give the file one owner and serialize the rest. |
| "This unit's check is obvious, I will skip the verifier." | A unit without a runnable `done_condition` is a stop row. Write the command and its exact last-line token. |
| "The architecture says 12 files, close enough." | Measure it. A measured value that contradicts a frozen fact stops the loop; re-measure first (D51). |
| "I will put a free port in the plan so launch is easy." | Candidates are a fixed formula, not promises. The launcher claims each per A.5.2; one claimed retry at candidate + 10, then stop. A plan-time clash is a stop, never a re-pick. |
| "I will run `port-check.sh` here to be sure." | The plan runs no port check. A reading now says nothing at launch time. |
| "A cross-wave `depends_on` is cleaner." | Edges name same-wave work_items only (rule 15). A dependent depends on its blocker's Integrator item in its own wave (AM-8 V13); wave order carries the rest. |
| "`max_concurrent` belongs in the spec." | It is a caller argument of `delivery-run`; the spec carries `dispatch_budget`. |
| "Plan-check is clean, review can skip it." | Plan-check comes first; every fix gets the G48 check and the checklist, and a fix to `waves/` or the unit table also gets a fresh checker. Round 3 ends with the owner (owner D7), never a fourth round. |
| "One more fix round will clear it." | Same finding class in two consecutive rounds replaces the mechanism (D60); a third round without `clean` stops. |
| "Gate rows in the plan can say TBD until dispatch." | A sentinel left in the plan fails the checklist; fill it or stop with the missing key named. |
| "Security audit can be a unit." | It is not a plan unit. It runs in `pre-pr-gate`; the plan only states slot use and row `C26`. |

## Exit criteria
- [ ] `dispatch-plan.md`, one `substate.seed.md` and one `waves/` per build-mode sub-task, one `.tasks/<unit>-<slug>.md` per unit, and an empty `RUN_HOME/catalog.tsv` exist.
- [ ] Every unit has one `done_condition` with a verifier, scope globs and a ticket; no scope overlap; every shared file has one owner.
- [ ] Port table, slot plan (`dispatch_budget`, peak, machine line of peak plus reserved against 200), `security_sensitive:` header and the computed Rule 7 note are in the plan.
- [ ] `references/predispatch-checklist.md` has no failing row and no `FILL_IN_BEFORE_DISPATCH` remains in any file this skill wrote.
- [ ] Line 1 of `RUN_HOME/plan-check.md` is `PLAN-CHECK: clean`, or the loop stopped at round 3 and the owner has been told (state which).
- [ ] The review loop ran at the rung `review-tailor` returned and ended at 0 blocking and 0 medium, or at round 3 with the owner told.
