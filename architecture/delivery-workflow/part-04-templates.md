## 5. Templates

Templates live in `references/templates/` of their owning skill; generated docs stay under about 500 lines. `INTERFACES.md` (W0) is the frozen home of every grammar below; after the freeze a change is a diffed amendment plus a consumer re-check list (M21).

### 5.0 `state.md`, `substate.md`, grammars (M21)
`state.md` (conductor): `run_id, repo_profile <path>@<sha>, delivery_root, stage, gates: {H0,H1,H-e2e[],H-pr[],H-prod[]: <path to gate file or external evidence>}, subtasks: [{id, session, lead_id, backend, state, pr, merge_sha, released_utc}], skill_versions: {name: version}, machine_ledger_row`. **Human gates (M30):** a verdict is never an agent-written field; it is a gate file `RUN_HOME/gates/<gate>.ok` the desk writes after the human types the confirmation in the desk session, or external evidence the desk reads back (H-pr: a GitHub approving review per §6.3 (part-05-execution-constraints.md); H1 may also be a human Jira comment or transition); `state.md` holds only the pointer; the desk refuses `jira-create` until `H1.ok` exists; the desk writes `H-e2e.<subtask>.ok` and the lead enforces it before generation, which is lead-side (INTERFACES A.2.1; erratum E8). The full `state.md` field list, including the fields added by later amendments (`security_audit`, `orchestrator_tier`, `interfaces_version` and the AM-5 re-entry fields), is INTERFACES A.2 (amended: AM-1, AM-3, AM-5). `substate.md` (lead): `subtask_id, session_id, live: <n>/30 (derived), reserved: {...}, frontier, waves_done, stop_reason`; beside it `bus.endpoint` (`port, data_dir, pm2_app, pid, session_id, topic`; INTERFACES D5, erratum E3), `inbox/` (conductor messages `RELEASE`, `INVALIDATE`, human answers), `gates/`. Slot row: `agent_id persona unit tier taken_utc budget_min worktree backend pid`. **Completion signal (B1, M15):** one canonical topic `<run-id>-<subtask>-rendezvous` on the bus whose `session_id` is `<run-id>-<subtask>` (pinned, stable across resume); the payload is the `output_schema` record `{"unit": "<id>", "verdict": "PASS|ROLLED|ESCALATE", "head": "<sha>", "reason": "<code>"}`; `PASS` frees the slot after the lead verifies `head`; `ROLLED` re-dispatches one tier up or marks the unit blocked; `ESCALATE` pauses the unit and the lead writes `RUN_HOME/<subtask>/escalations/<unit>.md` (INTERFACES C2, C5.1); fallback when the bus is unreachable: the same record in `status/<agent-id>.verdict`, picked up by the lead's tick. The conductor never reads a sub-task bus; it reads `state.md`, `substate.md` and inbox files. `NEXT: <step-id> <one line>` in `status/<agent-id>.md`. **Review record contract (M16):** `pr-review` writes `CODE-GATE-REVIEW: PASS head=<sha> blocking=0 medium=0`; the Verified-By seat appends `Verified-By: <seat-id> head=<sha>`; the desk re-derives both from the record path. Status vocabulary: Backlog, In Progress, In Review, Blocked, Verified, Done; mapped per repo profile to Jira statuses. Topics: `<run-id>-<subtask>-rendezvous` on the sub-task's own bus, and `pr-check-N-closed` literally on `pr-review`'s own local bus; there is no conductor topic, conductor messages travel only as inbox files. **`DELIVERY_ROOT` (M12):** one environment variable the executing human sets at the move, no default, created with `umask 077`; every skill fails loudly when it is unset; `RUN_HOME = $DELIVERY_ROOT/<run-id>`, desk mailbox `$DELIVERY_ROOT/<run-id>/desk`, desk inbox `$DELIVERY_ROOT/desk-inbox` (desk-owned); in a multi-repo epic the primary repo named in `architecture.md` §3 governs and the other profiles are linked.

### 5.1 Epic and child tickets (from the Jira ticket template and the typed-epic plan)
Header: issue type, team, epic link, priority, requested by. Body: Summary; Problem (background, current, expected, evidence); Impact; Business value; Requirements (functional; non-functional); Acceptance criteria as Gherkin (happy, failure or edge, observability) which also seed `.feature` files (§3.6 (part-03-personas-and-concurrency.md)); Dependencies; Risks; Subtasks. Epic additions: phases, dependency map, typed children, spikes first and timeboxed, open questions. Agent additions: scope globs, persona and tier, blocked-by, lanes, test expectations (unit, integration, e2e yes or no with reason), done token, verifier, budget. Lifecycle: local drafts until H1 ACCEPT; then `ticket-clerk` publishes through the desk in dependency order.

### 5.2 `architecture.md`
Header line `security_sensitive: yes|no` (required; it selects `security_audit` full mode and DOC-1 checks it; amended: AM-3 errata (a), erratum E29). 1 Summary (15 lines). 2 Goals and non-goals. 3 Components, interfaces, contracts. 4 Locked decisions with ADR references; open decisions. 5 Epic and sub-task tree with merge order (D5). 6 Scope: in, out, external open items. 7 Dispatch-plan requirement. 8 Testing plan pointer, including the e2e harness statement (present, or gap named, D17). 9 Release sketch pointer with the agent-run / human split (D15). 10 Risks and stop-the-line. 11 Diagrams as text. 12 Review record (rung, seats, rounds, open findings if round 3). 13 Human acceptance block: ACCEPT / CHANGES / REJECT, name, date (D1, D18). 14 Provenance. Large epics split into a landing page plus parts.

### 5.3 `dispatch-plan.md`
Header (epic, repos, `repo-profile.md` link plus sha, never a copy, D22). Sub-task table (id, PR, merge order, lead session, backend, slot plan, depends-on sub-task or `independent`, M19); sub-task 0 is the plan PR (M22); version-bump list of affected apps under `apps/` per sub-task (B3). Persona roster with tiers. Repo table. Unit table (id, ticket, scope globs, blocked-by, persona, lane, budget from measured medians, done token, verifier, review path, e2e new|updated|none). **Shared-file owner and serial-lane table** (M16) which also names the one owning document of every cross-unit contract (D63). DAG and wave sketch. Lane table with per-lane resource profile (HTTP, HMR and devtools ports, browser pre-staged by the desk `INSTALL`, device lanes human-run, A5). Parallelism note (computed). Shepherd cadence. Branching and merge order. Pre-PR gate rule. Cleanup rule. Pre-dispatch checklist. Stop-the-line table. Review rung table. Throughput formula: `sub-tasks x review minutes / parallel reviews`.

#### 5.3b Unit task spec (11 sections, from `XC/_templates/task-spec.md`)
Objective; Context package; Scope in, out, do-not-create; Contracts table; Inherited module API; What you inherit; Known risky values; Acceptance criteria; Verification commands; Branch and worktree; Decision Gate reminder. Pre-flight six checks: inherit present, risky values present, module API present, do-not-create present, criteria verifiable with the given commands, every risky value sourced from its authority contract.

### 5.4 `test-plan.md`
Strategy line and phase order from the repo profile. Pre-merge: per AC the test file and level; CI-parity row; standardization pre-check row; e2e rows (`.feature` path, Gherkin checkpoint date, generated spec path, `nl-run-e2e` result, auto-healed diffs reviewed yes/no); coverage thresholds from the profile. Post-merge: id, what it proves, command, lane, expected, evidence owner, cold-run, order or seed, gating or informational, failure policy, human hand-test rows where no harness exists (D17). Consumer-simulation rows. Test-management reporting row (desk). Explicitly-not-tested list.

### 5.5 `release-plan.md`
Scope; correlation id; version intent and gates; pre-release naming; environments and order; flags and config; migrations; **each step marked `agent` (staging deploy, polling, reporting) or `human` (production deploy, flag flip, money, prod data, external publication, store submission) with the exact prepared command** (D15); signals and thresholds; rollback criteria and command per step; pre-release cleanup rule; changelog and notification rows; published-artifact consumer simulation before stable publish; evidence per step; adjustment log.

### 5.6 `catalog.tsv` (M26)
`ts, run_id, subtask, row_id, correlation_id, kind (worktree|branch|tag|process|pm2-app|port|bus|tmpdir|container|image|lane-lease|db|clone|cron|bgtask|file|workspace), handle, owner_agent, unit, state (planned|live|released|failed|kept), keep_reason, source` (12 columns per INTERFACES A.5; `verify_cmd` dropped, M26, erratum E2). No executable column: `catalog.sh` derives `cleanup` and `verify` from a fixed per-kind table; handles must realpath under `RUN_HOME` or the registered worktree base; control characters and rows over 400 bytes are rejected; only the script appends (single-line `>>`, measured non-interleaving for 10 concurrent 600-byte appends; not stress-tested). `audit` classifies MATCH, GHOST, SQUATTER against `kill -0`, `lsof`, `git worktree list`, and exits 5 with no verdict when `lsof` is missing or failing (INTERFACES script table; amended: AM-5 PR10-M4).

### 5.7 Step-completeness checklist
Ticket linked and status correct; child coverage; branch rebased (sha); each AC has a test; each e2e row exists, its Gherkin checkpoint is recorded and its spec ran; `GATES` exit 0; CI-parity in order; standardization pre-check; **a `GATE-PASS` record for every pushed batch on the branch** (D21, R2-3); redaction gate clean; scope-check clean or each extra justified with an `INSTALLED` row or grant; reviewer record path and 0B/0M; Verified-By seat distinct from Reviewed-By; fixer shas with `fix:` fields; fix-verifier CLEAN; docs and changelog; migrations have rollback; no leftovers; adjacent defects ticketed; fix commits pushed; catalog has no `planned` rows; PR body from template; plan unit list equals branch unit list. `PASS` only if every row has evidence.

### 5.8 `repo-profile.md` (sole authority, D22, M17)
One file per target repo, under the repo's `plans/` or the context store as the profile's header says; every other doc links it with `@<sha>`. Fields: `PROJECT_ROOT` (feature worktree, never main checkout); `worktree_base` (under `$DELIVERY_ROOT`; the roots themselves come from `DELIVERY_ROOT`, M12); package scope and type; consumer repos; registry config; exact command strings (install as `--frozen-lockfile --ignore-scripts`, `install.rebuild_allowlist`, lint, typecheck, test, build, pack, clean, release, publish; `gates.command` with `--base`/`--head`/`--parallel`, `gates.runner_slots`, `gates.parallel`, `gates.min_free_kb`); `node.prefix_cmd` (one-shot, A2); the single `HUSKY=0` statement (inline per command, after `GATE-PASS`; M7); `pr.author_identity` and `pr.approval_rule` (R2-4, §6.3 (part-05-execution-constraints.md)); `merge_reach` (what a merge deploys, B3) and `version_bump_rule`; `plan_plane_pr` (M22); `ci.max_open_pr_pipelines`, `ci.min_push_spacing_s` (M9); `secrets.pattern_file` (M31); `zephyr.read_ops` and the Zephyr `execute` tool name `zephyr.execute_tool` (B2; erratum E36); secret retrieval by env-var name only; PR template path, label rules, commit pattern; CI system, required checks, status-read skill; merge method and route (D5); review profile (mandatory seats, Blocking rules); coverage thresholds; **sensitive-path deny list** (`sensitive_paths[]`, M25); **lane resource profile** (`ports.lane_base`, `ports.bus_base`, A5); key names per INTERFACES A.2.2, which also adds `default_branch`, `release_tags.*`, `review_profile.*` and `lanes[].db.cleanup_cmd` (amended: AM-2, AM-4, AM-5; erratum E36); `e2e.harness: nlta|none`, `e2e.context_file`, `e2e.plugin_source`, `e2e.prefix`, `e2e.auth_mode`, `e2e.mock_gate`, `e2e.dist_scan_cmd`, `e2e.remotes_resolution`, `e2e.serve_targets` (§3.6 (part-03-personas-and-concurrency.md)); test-management tool; Jira project key and status map; **measured durations** (`pr-review` round, CI round, unit median) for budgets (M15); pre-dispatch checklist with `FILL_IN_BEFORE_DISPATCH` sentinels. Note: the hq `wave-execution` port dropped command-token registries deliberately; the profile is the caller-side home for them.
