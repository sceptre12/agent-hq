### 2.2 NEW skill cards

Common to every card: tier names, not models (M19); no `disable-model-invocation` (D16); inputs and outputs are named and enum-validated (M22); Provenance per D14 where no friction exists yet; reviewer rung is the lowest that covers the risk (Rule 12).

**1. `delivery-pipeline`** (conductor). Trigger: "Use when the owner wants a change carried end to end by an agent team, or says run the delivery pipeline, next stage, resume." In: intent or `RUN_HOME`. Out: `state.md` (§5.0 (part-04-templates.md)), per-stage artifacts, one status post per gate. Steps: ORCHESTRATOR-CHECK (Agent tool present, not a subagent); resume from `state.md` after reboot reconciliation (§4 (part-03-personas-and-concurrency.md)); run the stage skill; record gate verdicts; refuse to skip H gates; arm the merged 10-minute tick (§4); spawn one sub-task lead session per sub-task through the launcher spec (§6.4 (part-05-execution-constraints.md): scrubbed environment, asserted `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`, fail-closed `--disallowedTools`; the conductor is the only launcher, A4/A5); send `RELEASE <subtask>` and `INVALIDATE <subtask> <reason>` to lead inboxes (M19); own stage 8 (retro, session dump, Hermes flush, read-back by a different agent; template pack dependency, A9); end of turn writes state and prints its path. Tier: design. Stop: any stop-the-line row; missing state at resume (rebuild from row files, then stop and report). Friction: Hermes `workflow-orchestration` ("main chat is a router"), brain-workflow-shift S1.

**2. `delivery-intake`** (stage 1). Trigger: "Use when starting a delivery run, before an architecture exists, to grill the human and shape the initial context." In: raw intent. Friction: grilling's own rule that facts are the agent's job; Hermes S2 unmeasured premise.

**3. `delivery-architecture`** (stage 2). Trigger: "Use when a confirmed brief must become an epic tree and a human-reviewable architecture doc with dispatch, testing and release sections." Steps: ORCHESTRATOR-CHECK; reconcile state against git refs, worktree list, catalog, `kill -0`; start the bus with `data_dir` under `RUN_HOME/<subtask>/bus/`, `session_id = <run-id>-<subtask>`, and write `RUN_HOME/<subtask>/bus.endpoint` (port, data_dir, pm2 app, pid) before any dispatch (B1); invoke the extended `wave-execution` in DAG-frontier mode with `session_id`, `output_topic = <run-id>-<subtask>-rendezvous`, `max_concurrent` = free slots, `persona`, `lane`, `gate_type: step_complete` (ADR 0023 amendment, §2.3); write the slot row file BEFORE each dispatch; collect the `UNIT-VERDICT` record from the canonical topic (or the `status/<agent>.verdict` fallback file, §5.0 (part-04-templates.md)), verify `head` with `git rev-parse` in the unit worktree, and re-run one load-bearing command (M15); escalate one tier up on failure, never a third attempt at the top tier; stop all then relaunch after any brief or path fix; dispatch the Integrator, the single writer of the sub-task branch, to integrate units serially, rebase first (M20); for fixers, one fixer per worktree at a time, else one worktree per fixer with disjoint file sets computed from the findings and serial integration (M18); on a successor sub-task, start only after `RELEASE` (M19); free a slot only after an accepted result or `TaskStop`; hand to `pre-pr-gate`.
