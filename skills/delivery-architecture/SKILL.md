## Trigger
Use when a confirmed brief must become an epic tree and a human-reviewable architecture doc with dispatch, testing and release sections (card 3, stage 2). The conductor invokes it after `gates/H0.ok` exists, and again after an `H1.changes` verdict (the notes bind). Model-invocable (D16).

Personas (part D2.1): you are the `architect` (design tier). You dispatch one `ticket-decomposer` (execute tier) with `references/decomposer-brief.md`; your own brief is `references/architect-brief.md`. Both carry the COMMON block; pass it unchanged to any agent you brief.

Outputs (part A.6, planes part D6): in `PLANS_DIR`: `drafts/<slug>.md`, `drafts/index.md`, `architecture.md`, `test-plan.md` v0, `release-plan.md` v0, `review-architecture.md`, `h1-packet.md`; at the repo root: `contracts/`. Every file is written to a temp file in its own directory and `mv`d into place (part A.1 atomic writes). Templates (item 27): `references/templates/{ticket,architecture,test-plan,release-plan}.md`; this skill never edits them.

## Steps
0. **Validate inputs (part D1, D2.2 row 3).** Inputs as `NAME=value`: `RUN_HOME` (path), `PLANS_DIR` (path; holds `brief.md`, `facts.md`), `REPO_PROFILE` (`<abs path>@<sha>`). Check every field and the profile keys this skill reads (`e2e.harness`, `durations.*`, `review_profile.*`), print one `INPUT-ERROR <NAME> <reason>` line per failing field, then stop: no retry, no prompt, nothing written. `RUN_HOME` absent prints exactly `INPUT-ERROR RUN_HOME missing`. Cases: `references/step0-inputs.md`. If `RUN_HOME/gates/H1.notes.md` exists and `RUN_HOME/gates/H1.changes` is live, this is a re-entry: read the notes first; every note is a binding change.
1. **Find existing docs; update, never duplicate (Rule 5).** Search the repo root (the parent of the `plans/` directory holding `PLANS_DIR`) for `docs/`, `architecture/`, `plans/*/architecture.md`, `contracts/`, ADRs and the files `brief.md` names. For each doc that covers the same surface: validate it against source (step 9 method) and plan an update; a stale doc is corrected, not copied. Record each found doc and its decision (update, cite, or out of scope) for `architecture.md` item 4 and item 14.
2. **Draft the typed tree, spikes first.** From `brief.md` and `facts.md`, outline one `Epic`, then `Spike` children for every unknown that blocks a design choice (each timeboxed, with its question and exit), then `Story`, `Task`, `Subtask` children. Types are exactly the D2.1 set `Epic|Spike|Story|Task|Subtask`. Merge order follows owner ruling D5 (one PR per sub-task). Rules: `references/tree-rules.md`.
3. **Mint slugs, write the drafts, then the index.** Mint one slug per node (`^[a-z0-9][a-z0-9-]*$`, never `index`, unique; rule in `references/tree-rules.md`). Dispatch the `ticket-decomposer` with the tree inline; it writes `drafts/<slug>.md`, each opening with YAML front matter of exactly `slug`, `issuetype`, `parent` (`-` for the epic), then the `templates/ticket.md` body: Gherkin AC (happy, failure or edge, observability) for every Story, agent additions (scope globs, persona and tier, blocked-by, lanes, test expectations with e2e yes or no and reason, done token, verifier, budget from `durations.*`). Validate every `issuetype` against D2.1 (`INPUT-ERROR issuetype enum` on a miss, then stop). Write `drafts/index.md` last: line 1 `DRAFTS: <n> drafts`, `<n>` the number of `drafts/*.md` other than `index.md`, then one row per draft in publish order (parents before children, spikes first). Drafts stay local until `H1.ok`; no `jira-create` here.
4. **Write `contracts/`.** One file per shared value or cross-unit contract (API shape, event, schema, config key, file format, fixed port). Each contract has exactly one owning document; siblings cite it by pin (`contracts/<file>@<sha>` or `<file>:<line>`) and never restate it (D63, D67). Rules: `references/contracts.md`.
5. **Write `architecture.md` in the part-04 §5.2 order** from `templates/architecture.md`: header block with exactly one line `security_sensitive: yes` or `security_sensitive: no` (step 5a), then items 1-14. Item 3 names every component, interface, contract (by pin) and every fixed port a component needs (port, bind, service, why fixed) so the dispatch plan and lanes can claim it with `tools/port-check.sh --claim` before launch (part A.5.2); this skill binds nothing, claims nothing and writes no catalog `port` row. Item 3 restates the primary repo and names any other repo (part A.1). Item 5 lists the tree by slug. Item 12 is filled at step 12. Item 13, the human acceptance block (ACCEPT / CHANGES / REJECT, name, date), is written blank. Link the profile `@<sha>`, never copy it (D22). Over about 500 lines: a landing page plus parts (`references/tree-rules.md` §Large epics).
   - 5a. **Set `security_sensitive`** from `references/security-sensitive.md` (plan-check default, pending owner OQ-1). When unsure, `yes`.
6. **Write `test-plan.md` v0** from `templates/test-plan.md` (part-04 §5.4). The e2e statement follows `e2e.harness` (D17; part-03 §3.6 step 1): `nlta`: every user-visible Story gets an e2e unit row (`.feature` path planned, flow named). `none`: `architecture.md` item 8 names the gap in one line per affected Story, and `test-plan.md` carries human hand-test rows post-merge for those Stories. Every Story AC maps to a test row.
7. **Write `release-plan.md` v0** from `templates/release-plan.md` (part-04 §5.5). The step table's first column is `step_id` (`^[a-z0-9-]+$`, unique in the plan; you mint the ids, `release-track` keeps them), then the step, its owner `agent` or `human` (D15: production deploy, flag flip, money, prod data, external publication, store submission are `human`), and the `tag` for a tag step; each step has its exact prepared command and rollback.
8. **Re-sync drafts.** Re-dispatch the decomposer (same brief) if steps 4-7 changed a child's scope, contract pin or test expectation; rewrite `drafts/index.md` after any draft change.
9. **Verify claims against source.** Every factual sentence in `architecture.md`, `contracts/` and the drafts cites a `facts.md` row or a command you ran (`measured: <cmd -> result>`); a design choice that is not a fact (a new endpoint path, an error code) is marked `proposed`. Re-run the command behind each load-bearing fact. A doc that contradicts source is the stop condition: re-measure, fix the doc; if a `facts.md` row itself is wrong, stop and report it to the conductor (the fact is re-measured before anything else, D51).
10. **Call `review-tailor`.** Mint `SLUG=run-doc-<n>`, `n` = 1 + the number of existing `RUN_HOME/review-tailor-run-doc-*.md`. Pass `RUN_HOME`, `SLUG`, `ARTIFACTS` (comma-separated absolute paths: `architecture.md`, its parts, `contracts/*`, `test-plan.md`, `release-plan.md`, `drafts/*.md`), `KIND=doc`, `STAKES`, `CONTENTION`, `NOVELTY`, `SECURITY_AUDIT`. Values and the guidance-versus-full rule: `references/review-handoff.md`. Read `RUN_HOME/review-tailor-<SLUG>.md`: line 1 must match `^RUNG: (0|1|2|2b|3|4) seats: [0-9]+$` (`INPUT-ERROR rung enum` otherwise, then stop). Card 3 floor: 1 for a story, 2b for an epic, 4 for a one-way door; a rung below the floor is reported to the conductor, not run.
11. **Run the loop the record names** (`references/review-handoff.md`): Rung 1 `doc-reviewer` with `skills/doc-reviewer/references/delivery-doc-checks.md`, fix, `fix-verifier`; Rung 2 `panel-consultation`; Rung 2b `review-7-panel`; Rung 4 `panel-review`. One review orchestrator per loop (D35). The G48 pre-round check runs before round 1 and after every fix, and its fails are fixed before any seat reads. Relay the D57 freeze trigger stated in the record into the orchestrator brief. A finding that arrives mid-round is queued for the next round start or a separate pass, never injected (G46). The fixer is never you, the author; `fix-verifier` runs after each fix. Stop at 0 Blocking / 0 Medium, or after round 3 (owner ruling D7): the open findings go to the packet and the owner decides.
12. **Child-coverage and template-format checks.** Run every check in `references/tree-rules.md` §Checks and paste each result into the review record. A failure is fixed (by the loop's fixer, then `fix-verifier`) before step 13. Fill `architecture.md` item 12 (rung, seats by link, rounds, open findings if round 3 was reached).
13. **Write the review record.** Write `review-architecture.md` to a temp file in `PLANS_DIR`: line 1 exactly `ARCH: ready`; then the record body (rung, mechanism, rounds, final B/M/L, check results, queued findings, open findings if round 3) and a link to `RUN_HOME/review-tailor-<SLUG>.md`; the seat table is linked, not copied (D22). Do not move it into place yet.
14. **Write `h1-packet.md`** (one page, `references/h1-packet.md`): decisions needed, risks, open findings if round 3 was reached, what the human is accepting (each artifact with its sha256). It tells the human the desk line `GATE <run-id> H1 ok|changes|reject <text>` (part B8). Then `mv` the review record into place, so `ARCH: ready` is the last thing written.
15. **Stop.** Hand the packet path to the conductor. H1 is the desk's and the human's: you write no gate file and publish nothing.

## Red flags
| Rationalization | What to do instead |
|---|---|
| "The sibling contract is short; I'll restate it here for readability." | Cite it by pin. One owning document per cross-unit contract (D63, D67); a restatement is the cross-document conflict reviews keep finding. |
| "The human will accept anyway; I'll create the Jira tickets now." | Drafts stay local. `ticket-clerk` publishes through the desk only after `RUN_HOME/gates/H1.ok` exists. |
| "This epic looks small, skip the loop." | Call `review-tailor` and run the mechanism it names. The rung floor is card 3's, not your judgement. |
| "That number is well known; no need to cite it." | Every fact cites a `facts.md` row or a command you ran. No measured source, no fact. |
| "A seat just found something; I'll pass it to the running round." | Queue it for the next round start or a separate pass (G46). |
| "The doc disagrees with the code; the doc is probably newer." | Measure. The doc contradicting source is the stop condition. |
| "I'll fix the review findings myself; I know the doc best." | The fixer is never the author. You hand findings to the loop's fixer. |
| "Round 3 still has a Medium; one more round will close it." | D7: stop after round 3; the open findings go in the packet for the owner. |
| "There is an old architecture doc, but starting fresh is cleaner." | Update the existing doc (Rule 5); a stale doc is corrected, not duplicated. |
| "The repo has no e2e harness, so e2e does not apply." | Name the gap in `architecture.md` item 8 and add human hand-test rows to `test-plan.md` (D17). |
| "The service needs port 4200; I'll claim it now to be safe." | Name the port in item 3. The dispatch plan and lanes claim it before launch (A.5.2); this skill claims nothing. |
| "The epic touches auth, so I'll run `security-audit` now." | Write `security_sensitive: yes`; the conductor sets `SECURITY_AUDIT`. This skill runs no audit and writes no audit files. |
| "I'll copy the profile values into the doc." | Link `REPO_PROFILE` `@<sha>` (D22). |
| "I'll write `ARCH: ready` first so the conductor sees progress." | It is written last, after the loop and the checks, with the packet already in place. |

## Exit criteria
- [ ] Step 0 passed, or only `INPUT-ERROR` lines were printed and nothing was written.
- [ ] Existing docs found in step 1 were updated or cited, none duplicated.
- [ ] `drafts/index.md` line 1 matches `^DRAFTS: [0-9]+ drafts$` and `<n>` equals the number of drafts; every draft stem matches `^[a-z0-9][a-z0-9-]*$`, is not `index`, and its front matter is exactly `slug`, `issuetype` (D2.1), `parent`; exactly one `Epic`, with `parent: -`; every other `parent` is a draft slug.
- [ ] Every draft Story has Gherkin AC with a happy path and a failure path.
- [ ] Every cross-unit contract has exactly one owning document; no sibling restates it.
- [ ] Every user-visible Story has an e2e unit (`nlta`) or a gap line in `architecture.md` item 8 plus human hand-test rows in `test-plan.md` (`none`).
- [ ] `architecture.md` has items 1-14 in order, exactly one `security_sensitive: yes|no` header line, fixed ports named in item 3, and a blank item 13.
- [ ] `release-plan.md` step ids match `^[a-z0-9-]+$`, are unique, and every step is `agent` or `human`.
- [ ] The loop reached 0 Blocking / 0 Medium, or stopped after round 3 with the open findings in the packet.
- [ ] Every check of `references/tree-rules.md` §Checks passed and its result is in the review record.
- [ ] `review-architecture.md` line 1 is exactly `ARCH: ready`, it links `RUN_HOME/review-tailor-<SLUG>.md`, and it was moved into place after `h1-packet.md`.
- [ ] No draft was published, no gate file written, no port claimed, no audit run, no web fetched, no money or spend metric written (B-4).
